# ZELVOLT ゲームフロー仕様 v0.2

この文書は `ZELVOLT_PLAN.md` の確定スペックを前提に、通常遊技からボーナス終了までの操作・状態遷移を定義する。

## 基本方針

ZELVOLTは技術介入なしのノーマルタイプ。

- 通常時は `BET → START → STOP×3` のみ
- 毎ゲーム独立抽選
- 押し順なし
- 目押しによる獲得差なし
- 取りこぼしなし
- ボーナス成立後の内部高確率・連チャンモードなし
- BIG / REG終了後は即通常状態へ戻る

## 状態遷移

```text
NORMAL_READY
  ↓ BET
NORMAL_BET
  ↓ START / レバー
NORMAL_SPIN
  ↓ STOP×3
NORMAL_RESULT
  ├─ ハズレ / 小役 / リプレイ → NORMAL_READY
  └─ BIG / REG成立 → BONUS_HIT
                         ↓ 入賞表示
                    BONUS_START
                         ↓
                 BIG_PLAY / REG_PLAY
                         ↓
                    BONUS_END
                         ↓
                    NORMAL_READY
```

内部状態名は実装時に変更してよいが、ゲーム上の意味はこの順序を維持する。

## 通常ゲーム

### 1. BET

- 通常時は3枚掛け
- BET完了後にSTARTを受け付ける
- リプレイ成立後は次ゲームの3枚投入を不要とする

### 2. START / レバー

START入力時に、そのゲームの結果を1回だけ抽選する。

抽選対象:

- BIG
- REG
- リプレイ
- ベル
- ブドウ
- チェリー
- STAR
- ハズレ

抽選結果はリール停止前に内部確定し、STOP操作で当否を変更しない。

BIG成立時は同時に図柄を決定する。

- 赤7: 80%
- 白紫7: 20%

赤7 / 白紫7は演出上の違いのみで、どちらも純増600枚BIG。

### 3. リール回転 / STOP

- 3リールはSTART後に回転
- STOPボタンは左・中・右を任意順で押せる
- 押し順による有利不利はない
- STOPタイミングによる払い出し差はない
- 内部抽選結果に応じて停止制御側が成立役を保証する

プレイヤーはリールを止める操作感を持つが、技術介入は発生しない。

## 小役・リプレイ成立時

3リール停止後に成立役を表示し、払い出しを行う。

- リプレイ: 再遊技
- ベル: 10枚
- ブドウ: 8枚
- チェリー: 2枚
- STAR: 15枚

STARは強い雷フラッシュ等の演出起点にできるが、成立後のボーナス確率は上昇しない。

## ボーナス成立ゲーム

### 告知

BIG / REG成立ゲームでは、STARTから第3停止までのどこかで告知演出を発生させる。

初期実装では複雑な告知比率を作らず、以下を基準とする。

- START時: 筐体上部または告知ランプが短く反応
- リール停止中: 雷エフェクトを段階的に強化
- 第3停止: ボーナス図柄停止と同時に確定告知

告知タイミングは演出上の違いであり、ボーナス期待度や性能差は持たせない。

### ボーナス図柄

技術介入なしを守るため、ボーナス成立ゲームではSTOPタイミングに関係なく停止制御で対応図柄を入賞させる。

- BIG（赤7選択時）: 赤7揃い
- BIG（白紫7選択時）: 白紫7揃い
- REG: BAR揃い

「狙わないと揃わない」「揃えるまでコインを追加消費する」という仕組みは採用しない。

第3停止で図柄が揃った時点で通常ゲームを終了し、ボーナス開始演出へ移行する。

## BIG

確定仕様:

- **55G**
- **純増600枚**
- 3枚投入/G
- 1G最大15枚払出
- ボーナス中の追加ボーナス抽選なし
- 終了後は即通常

55Gでは総投入165枚。純増600枚に必要な総払出は765枚で、平均払出は約13.91枚/Gとなる。最大15枚/Gの範囲内に収まり、毎ゲーム15枚固定にせず払い出しの揺らぎを持たせられる。

操作:

- BIG中も基本操作は `START → STOP×3`
- BET操作は自動化可能とし、テンポを通常時より速くする
- 各ゲームで払い出し演出を行い、CREDIT / PAYを増加させる
- 最終ゲーム終了時にBIG区間全体の差枚が純増+600枚になるよう管理する

BIG中は黄×黒・雷モチーフを全面発光させ、通常時との差を明確にする。

## REG

確定仕様:

- **14G**
- **純増120枚**
- 3枚投入/G
- 1G最大15枚払出
- ボーナス中の追加ボーナス抽選なし
- 終了後は即通常

14Gでは総投入42枚。純増120枚に必要な総払出は162枚、平均払出は約11.57枚/Gとなるため15枚上限内で成立する。

操作はBIGと同じく `START → STOP×3` を基本とする。

BIGより演出・BGM・発光量を抑え、ボーナス種別が一目で判別できるようにする。

## BONUS END

BIG / REG最終ゲーム後に結果表示を行う。

表示候補:

- BONUS種別
- GET枚数
- ボーナス消化G
- 現在CREDIT
- 当日BIG回数
- 当日REG回数
- 現在差枚

結果表示後は追加抽選や高確率状態を挟まず `NORMAL_READY` へ戻る。

## パチ朗ホールへ同期するイベント

最低限、以下のタイミングで親側へ状態を送る。

- 通常ゲーム終了
- BIG成立
- REG成立
- ボーナス開始
- ボーナス中のCREDIT変動
- BIG終了
- REG終了
- 実機画面からホールへ戻る

同期値:

- machineId
- setting
- credit / playerMedals
- totalGames
- bigCount
- regCount
- differenceCoins
- currentState
- currentBonusType

## 実装上の重要ルール

- 抽選結果とリール表示を分離する
- STOP入力は結果変更に使わない
- 演出結果から抽選結果を逆算しない
- ボーナス中に通常時抽選を混ぜない
- CREDITはパチ朗ホール側の所持メダルと一貫して同期する
- 旧ペカチュウの挙動を一括で壊さず、状態管理 → 抽選 → リール停止 → ボーナスの順に段階移行する

## ボーナス消化ゲーム数の整合性

実機寄りの制約として **1ゲーム最大15枚払出** を採用する。

- BIG: 55G × 3枚 = 165枚投入。純増600枚には総払出765枚が必要。平均約13.91枚/G。
- REG: 14G × 3枚 = 42枚投入。純増120枚には総払出162枚が必要。平均約11.57枚/G。

これにより旧案のBIG 42Gで生じていた15枚上限との矛盾を解消する。以後の設計・実装では **BIG 55G / REG 14G** を基準とする。
