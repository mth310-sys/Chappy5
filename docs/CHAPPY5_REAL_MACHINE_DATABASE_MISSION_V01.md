# Chappy5 実機性能「物差し」データ収集ミッション v0.4

更新日: 2026-08-31

## 目的

5号機初期から2026年現行までの実在パチスロ機をサンプルとして、将来の架空機設計で

**「この系統の台なら、このくらいの性能が現実的」**

と判断できる数値の物差しを作る。

実機を完全再現するための解析DBではない。物差し作成に必要な共通性能値を、メーカー公式・公的資料・信頼できる攻略/解析サイトから広く集める。

## 最優先で集める共通データ

1. machineName — 機種名
2. manufacturer — メーカー
3. releaseDate — 導入時期
4. generation — 世代/規格
5. systemType — ノーマル、RT、ART、A+ART、AT、スマスロAT等
6. payoutRateBySetting — 設定別機械割/出玉率
7. initialHitBySetting — 主要初当たり確率
8. baseGamesPer50 — 50枚あたりゲーム数/ベース
9. netIncrease — 純増（該当機のみ）
10. basicPayout — ボーナス/AT等の基本獲得枚数

これらを物差し作成の中心値とする。

## 方式別の最低追加データ

### ノーマル / ボーナス主体
- BB確率（設定別）
- RB確率（設定別）
- BB獲得枚数
- RB獲得枚数

### ART / AT
- ART/AT初当たり（設定別で公開されている範囲）
- 純増
- 基本となる1セットG数/枚数または基本獲得性能

### CZが初当たり構造上重要な機種
- CZ初当たり確率

### 上位ATが性能を大きく左右するスマスロ
- 上位ATの純増
- 上位ATの基本性能について、比較に必要な公開数値が明確に取れる場合のみ追加

### 技術介入機
- 通常/市場掲載の機械割
- 完全攻略時機械割

## 補助データ

物差しの分類に必要な場合のみ記録する。
- 25φ / 30φ
- メダル機 / スマスロ
- 天井
- 特殊な設定構成（設定L等）

## 原則として集めない詳細解析

- 全小役確率
- モード移行率
- 上乗せ契機別振り分け
- 特化ゾーン詳細振り分け
- 演出期待度
- 設定示唆演出
- 終了画面振り分け
- 内部状態移行の詳細
- CZ中の細かな抽選値
- 実機再現のためだけに必要な解析値

後で特定機種を深掘りする必要が生じた場合のみ別途取得する。

## 今回は市場実績を集めない

以下は第2段階の市場DB候補とし、今回の必須収集から外す。
- アウト
- 台売上
- 台粗利
- コイン単価
- 中古価格
- 稼働貢献週
- 導入台数/市場シェア
- 人気ランキング

性能物差しが完成してから、必要に応じて取得可能な機種へ市場実績を追加する。

## 物差しの作り方

十分な実機サンプルが集まった系統について、同一条件の数値を比較し、以下を算出する。

- サンプル数
- 最小値
- 最大値
- 中央値
- 平均値（意味がある項目のみ）
- 代表的なレンジ

平均値だけで系統を定義しない。外れ値や時代差を確認し、必要なら同じATでも世代/構造で系統を分割する。

最終的には例えば、

`5号機高純増AT -> 設定1出率レンジ / 設定6出率レンジ / 初当たりレンジ / ベースレンジ / 純増レンジ / 基本獲得性能レンジ`

のような物差しを作る。

## 系統分類

最初から主観的な「マイルド」「荒波」だけで固定しない。

まず実機の事実上の方式と世代で分類する。
例:
- 5号機ノーマル
- 5号機A+ART
- 5号機ART
- 5号機AT
- 5.5/5.9号機ART/AT
- 6号機初期AT
- 6.5号機AT
- スマスロAT
- 沖スロノーマル
- 技術介入系

データ分布に明確な差が確認できた場合、そこから物差し用の下位系統を追加する。

## 情報源優先順位

1. メーカー公式
2. 公的/業界一次資料
3. 信頼できる攻略・解析サイト
4. 複数解析サイトの一致
5. 単一二次資料

古い5号機で公式ページが残っていない場合は当時の解析資料/アーカイブを使用してよい。

## 信頼度

- OFFICIAL
- INDUSTRY
- ANALYSIS_HIGH
- ANALYSIS_SINGLE
- UNVERIFIED
- CONFLICT

推定値は原則として物差しの元データへ入れない。

## 絶対ルール

- 不明値を推測で埋めない。
- 情報源間で違う値は平均せずCONFLICTとして保持する。
- 約/平均/最大/期待値を混同しない。
- 単位を必ず残す。
- 解析値とメーカー公表値を区別する。
- 出典URLと取得日を保存する。
- 同名シリーズ/別スペックを混同しない。
- 欠損が多い機種を無理に物差し計算へ使用しない。

## 保存形式

GitHubを正本とする。

`docs/real_machine_db/INDEX.md`
`docs/real_machine_db/machines/*.md`
`docs/real_machine_db/yardsticks/*.md`

最初はMarkdownで収集し、件数が増えて集計が必要になった段階でJSON/CSV等の機械可読データを生成する。

## Chappy5 分担

1. 5号機前半収集
2. 5号機後半収集
3. 5.5/5.9〜6号機初期収集
4. 6号機中後期〜スマスロ/2026現行収集
5. QA + 系統別物差し集計

QA担当は数値の正誤だけでなく、異なる定義の値を同じ列で比較していないかも監査する。

## 完成イメージ

架空機を設計するときに、

**「○号機の○○系統で、少し当たりが軽め」**

と指定すれば、実機群から作った物差しを参照して、現実から逸脱しにくい設定別出率・初当たり・ベース・純増・獲得性能の候補レンジを提示できる状態を目指す。

実機個別データは目的ではなく、信頼できる物差しを作るための根拠データである。
