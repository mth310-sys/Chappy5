# Chappy5 実機性能「物差し」データ収集ミッション v0.7

更新日: 2026-08-31

## 目的

5号機初期から2026年現行までの実在パチスロ機を広く収集し、将来の架空機設計で **「この系統の台なら、このくらいの性能が現実的」** と判断できる数値の物差しを作る。

実機を完全再現するための解析DBではない。物差し作成に必要な共通性能値に加え、ホール経営ゲームで設定変更・据え置き・朝一客行動を再現するためのリセット特性を収集する。

## 収集範囲 — 最重要

- 対象期間は **5号機初期〜2026年現行**。
- 代表機だけを抽出する方式ではない。
- **原則として期間内の全パチスロ機種を収集対象とし、件数上限を設けない。**
- 取得不能・資料不足の機種も対象外にせず、欠損を明示して次へ進む。
- 収集順は原則、導入時期の古い機種から新しい機種へ時系列で進める。

## 最優先で集める共通データ

1. machineName — 機種名
2. manufacturer — メーカー
3. releaseDate — 導入時期
4. generation — 世代/規格
5. systemType — ノーマル、RT、ART、A+ART、AT、スマスロAT等
6. payoutRateBySetting — 設定別機械割/出玉率
7. initialHitBySetting — 主要初当たり確率
8. baseGamesPer50 — 50枚あたりゲーム数/ベース
9. netIncrease — 純増（該当機のみ）
10. basicPayout — ボーナス/AT等の基本獲得枚数

## 方式別の最低追加データ

### ノーマル / ボーナス主体
- BB確率（設定別）
- RB確率（設定別）
- BB獲得枚数
- RB獲得枚数

### ART / AT
- ART/AT初当たり（設定別で公開されている範囲）
- 純増
- 基本となる1セットG数/枚数または基本獲得性能

### CZが初当たり構造上重要な機種
- CZ初当たり確率

### 上位ATが性能を大きく左右するスマスロ
- 上位ATの純増
- 上位ATの基本性能について、比較に必要な公開数値が明確に取れる場合のみ追加

### 技術介入機
- 通常/市場掲載の機械割
- 完全攻略時機械割

## 設定変更・リセット特性 — ホール経営シミュレーション用

実機内部を完全再現する目的ではなく、**店側の設定変更/据え置き判断 → 客の朝一狙い → 稼働・収益への影響**を再現できる粒度で収集する。

### 必須で確認する項目

各機種について公開情報を探索し、該当しない場合もその旨を記録する。

- settingChangeBehavior — 設定変更時の基本挙動
- carryOverBehavior — 据え置き時の基本挙動
- powerCycleBehavior — 電源OFF→ONのみの場合の挙動（設定変更と差がある場合）
- gameCounterReset — 前日/内部ゲーム数・天井ゲーム数がリセットか引継ぎか
- ceilingAfterReset — リセット時の天井短縮・変更の有無と数値
- modeAfterReset — モード再抽選/引継ぎと、朝一専用モード等の有無
- stateAfterReset — 内部状態の再抽選/引継ぎ
- advantageousSectionReset — 有利区間の扱い（該当世代のみ）
- resetBenefits — 朝一/設定変更時の主要恩恵
- resetPenalties — 設定変更時の主要な不利要素が公開されている場合
- resetDetection — ガックン、表示、ゲーム数挙動など客側から設定変更/据え置きを推測できる主要要素

### 公開数値がある場合に取得する項目

客の朝一行動を左右する比較可能な数値は取得する。

- 設定変更時のモード振り分け
- 朝一特定ゲーム数以内の当選率/期待度
- 短縮天井ゲーム数
- リセット恩恵の発生率
- 設定変更時のみ適用される主要な初当たり/CZ等の数値

ただし、設定変更の影響を説明するために必要な範囲へ限定する。

### 原則として取得しないリセット関連詳細

- 通常時の全モード移行テーブル
- 全小役別の状態昇格/転落率
- CZ内部の詳細抽選
- 前兆ゲーム数の全振り分け
- 上乗せ/特化ゾーンの内部抽選
- 実機を1:1再現するためだけの内部解析

**リセット時だけ適用され、朝一客の判断やホール収益へ明確に影響する値は例外として取得可。**

## 補助データ

物差しの分類に必要な場合のみ記録する。
- 25φ / 30φ
- メダル機 / スマスロ
- 天井
- 特殊な設定構成（設定L等）

## 原則として集めない詳細解析

- 全小役確率
- 通常時の全モード移行率
- 上乗せ契機別振り分け
- 特化ゾーン詳細振り分け
- 演出期待度
- 設定示唆演出
- 終了画面振り分け
- 内部状態移行の詳細
- CZ中の細かな抽選値
- 実機再現のためだけに必要な解析値

## 今回は市場実績を集めない

以下は第2段階の市場DB候補とし、今回の必須収集から外す。
- アウト
- 台売上
- 台粗利
- コイン単価
- 中古価格
- 稼働貢献週
- 導入台数/市場シェア
- 人気ランキング

## 物差しの作り方

十分な実機サンプルが集まった系統について、同一条件の数値を比較し、サンプル数・最小値・最大値・中央値・意味がある場合の平均値・代表レンジを算出する。平均だけで系統を定義せず、外れ値や時代差を確認する。

## 情報源優先順位

1. メーカー公式
2. 公的/業界一次資料
3. 信頼できる攻略・解析サイト
4. 複数解析サイトの一致
5. 単一二次資料

古い5号機で公式ページが残っていない場合は当時の解析資料/アーカイブを使用してよい。

## 欠損判定の前に行う再探索 — 必須

**最初の検索で見つからないことを理由に `UNVERIFIED` / `PARTIAL` で終了してはいけない。**

物差し値またはリセット特性が欠ける場合は、機種名の表記揺れ・正式型式名・略称・メーカー名・シリーズ名を変え、欲しい値に応じて「設定変更」「リセット」「朝一」「据え置き」「電源OFF ON」「天井短縮」「モード移行」「モード振り分け」「ガックン」「有利区間」も含めて検索語を変える。メーカー公式、業界記事、当時の攻略/解析サイト、古い機種DB、保存アーカイブ、後年の回顧資料を横断する。1サイトで終わらず別系統資料を確認し、発見値は可能な限り別ソースで照合する。

競合する数値は平均せず `CONFLICT` とし双方を残す。十分な再探索後も確認できない値だけを `UNVERIFIED` とする。

## 信頼度

- OFFICIAL
- INDUSTRY
- ANALYSIS_HIGH
- ANALYSIS_SINGLE
- UNVERIFIED
- CONFLICT

推定値は原則として元データへ入れない。

## 絶対ルール

- 不明値を推測で埋めない。
- 情報源間で違う値は平均せずCONFLICTとして保持する。
- 約/平均/最大/期待値を混同しない。
- 単位を必ず残す。
- 解析値とメーカー公表値を区別する。
- 出典URLと取得日を保存する。
- 同名シリーズ/別スペックを混同しない。
- 欠損判定前に検索語・資料系統を変えて再探索する。
- リセット特性は実機完全再現ではなく、ホール経営・朝一客AIに必要な粒度を守る。

## 既存レコードへの遡及適用

- 既存の全機種にも `resetBehavior` を遡及追加する。
- 新規機種収集を止めず、QAリレー時に既存PARTIAL/COMPLETE_CORE機を順次補完する。
- 既存の `COMPLETE_CORE` は従来の性能コア完了を意味する。リセット特性のQA状態は別途記録し、過去の完了判定を不用意に崩さない。
- リセット情報が存在しない/影響がないことを確認できた場合も、空欄ではなく確認結果を残す。

## Chappy5 作業方式 — リレー

年代別の固定担当制は採用しない。全作業者が同じ収集キューを順番に引き継ぐ。

毎回、最新mainの `README.md` → 本ミッション → `docs/real_machine_db/INDEX.md` → 既存機種レコード → 直前の再開地点、の順に確認する。直前の作業者が完了した次の未処理機種から再開し、作業終了時にINDEXへ完了範囲と次回再開地点を明示する。

新規機種では性能コアとリセット特性を同時に収集する。QAでは既存機種のリセット特性も遡及補完する。並列で別年代へ分岐せず、既収集性能値を最初からやり直さない。

## 完成イメージ

架空機を設計するときに実機群から現実的な性能レンジを提示でき、さらにホール経営シミュレーションでは、機種ごとの設定変更・据え置き・朝一特性を使って、店のリセット運用に対する客の狙いと稼働変化を再現できる状態を目指す。
