# Chappy5 実機性能「物差し」データ収集ミッション v0.6

更新日: 2026-08-31

## 目的

5号機初期から2026年現行までの実在パチスロ機を広く収集し、将来の架空機設計で **「この系統の台なら、このくらいの性能が現実的」** と判断できる数値の物差しを作る。

実機を完全再現するための解析DBではない。物差し作成に必要な共通性能値を、メーカー公式・公的資料・信頼できる攻略/解析サイトから広く集める。

## 収集範囲 — 最重要

- 対象期間は **5号機初期〜2026年現行**。
- 代表機だけを抽出する方式ではない。
- **原則として期間内の全パチスロ機種を収集対象とし、件数上限を設けない。**
- 取得不能・資料不足の機種も対象外にせず、欠損を明示して次へ進む。
- 広さを最大化するため、1機種あたりの取得項目は物差し作成に必要な値へ絞る。
- 収集順は原則、導入時期の古い機種から新しい機種へ時系列で進める。

## 最優先で集める共通データ

1. machineName — 機種名
2. manufacturer — メーカー
3. releaseDate — 導入時期
4. generation — 世代/規格
5. systemType — ノーマル、RT、ART、A+ART、AT、スマスロAT等
6. payoutRateBySetting — 設定別機械割/出玉率
7. initialHitBySetting — 主要初当たり確率
8. baseGamesPer50 — 50枚あたりゲーム数/ベース
9. netIncrease — 純増（該当機のみ）
10. basicPayout — ボーナス/AT等の基本獲得枚数

## 方式別の最低追加データ

### ノーマル / ボーナス主体
- BB確率（設定別）
- RB確率（設定別）
- BB獲得枚数
- RB獲得枚数

### ART / AT
- ART/AT初当たり（設定別で公開されている範囲）
- 純増
- 基本となる1セットG数/枚数または基本獲得性能

### CZが初当たり構造上重要な機種
- CZ初当たり確率

### 上位ATが性能を大きく左右するスマスロ
- 上位ATの純増
- 上位ATの基本性能について、比較に必要な公開数値が明確に取れる場合のみ追加

### 技術介入機
- 通常/市場掲載の機械割
- 完全攻略時機械割

## 補助データ

物差しの分類に必要な場合のみ記録する。
- 25φ / 30φ
- メダル機 / スマスロ
- 天井
- 特殊な設定構成（設定L等）

## 原則として集めない詳細解析

- 全小役確率
- モード移行率
- 上乗せ契機別振り分け
- 特化ゾーン詳細振り分け
- 演出期待度
- 設定示唆演出
- 終了画面振り分け
- 内部状態移行の詳細
- CZ中の細かな抽選値
- 実機再現のためだけに必要な解析値

## 物差しの作り方

十分な実機サンプルが集まった系統について、同一条件の数値を比較し、サンプル数・最小値・最大値・中央値・意味がある場合の平均値・代表レンジを算出する。平均だけで系統を定義せず、外れ値や時代差を確認する。

## 系統分類

まず実機の事実上の方式と世代で分類する。例: 5号機ノーマル、5号機A+ART、5号機ART、5号機AT、5.5/5.9号機ART/AT、6号機初期AT、6.5号機AT、スマスロAT、沖スロノーマル、技術介入系。データ分布に明確な差が確認できた場合のみ下位系統を追加する。

## 情報源優先順位

1. メーカー公式
2. 公的/業界一次資料
3. 信頼できる攻略・解析サイト
4. 複数解析サイトの一致
5. 単一二次資料

古い5号機で公式ページが残っていない場合は当時の解析資料/アーカイブを使用してよい。

## 欠損判定の前に行う再探索 — 必須

**最初の検索で見つからないことを理由に `UNVERIFIED` / `PARTIAL` で終了してはいけない。**

物差し作成に必要な値が欠ける場合は、少なくとも以下を行う。

1. 機種名の表記揺れ、正式型式名、略称、メーカー名、シリーズ名を変えて検索する。
2. 欲しい値に応じて「設定差」「設定別」「機械割」「出玉率」「BIG確率」「REG確率」「ボーナス合算」「初当たり」「50枚」「1000円」「ベース」「純増」「獲得枚数」等、検索語を変える。
3. メーカー公式だけでなく、業界記事、当時の攻略/解析サイト、古い機種DB、保存アーカイブ、後年の回顧資料を横断する。
4. 1サイトで見つからなくても、別系統の資料を複数確認する。
5. 古い機種では、現在のSEO上位だけに依存せず当時資料やアーカイブを積極的に探す。
6. 数値を発見したら、可能な限り別ソースで照合し、定義・単位・設定番号・別スペック混同がないか確認する。
7. 競合する数値は平均せず `CONFLICT` とし、双方の出典と値を残す。

上記を行っても確認できない値だけを `UNVERIFIED` とする。`PARTIAL` は「情報が存在しない」の意味ではなく「十分な探索後も未確定が残る」の意味として扱う。

## 信頼度

- OFFICIAL
- INDUSTRY
- ANALYSIS_HIGH
- ANALYSIS_SINGLE
- UNVERIFIED
- CONFLICT

推定値は原則として物差しの元データへ入れない。

## 絶対ルール

- 不明値を推測で埋めない。
- 情報源間で違う値は平均せずCONFLICTとして保持する。
- 約/平均/最大/期待値を混同しない。
- 単位を必ず残す。
- 解析値とメーカー公表値を区別する。
- 出典URLと取得日を保存する。
- 同名シリーズ/別スペックを混同しない。
- 欠損が多い機種を無理に物差し計算へ使用しない。
- 欠損判定前に検索語・資料系統を変えて再探索する。

## Chappy5 作業方式 — リレー

年代別の固定担当制は採用しない。全作業者が同じ収集キューを順番に引き継ぐ。

毎回、最新mainの `README.md` → 本ミッション → `docs/real_machine_db/INDEX.md` → 既存機種レコード → 直前の再開地点、の順に確認する。直前の作業者が完了した次の未処理機種から再開し、作業終了時にINDEXへ完了範囲と次回再開地点を明示する。

並列で別年代へ分岐せず、既収集機種を最初からやり直さない。QAは収集を止めず適宜行う。PARTIAL機種はQA対象として再探索し、簡単に欠損確定しない。

## 完成イメージ

架空機を設計するときに **「○号機の○○系統で、少し当たりが軽め」** と指定すれば、実機群から作った物差しを参照して、現実から逸脱しにくい設定別出率・初当たり・ベース・純増・獲得性能の候補レンジを提示できる状態を目指す。

実機個別データは目的ではなく、信頼できる物差しを作るための根拠データである。
