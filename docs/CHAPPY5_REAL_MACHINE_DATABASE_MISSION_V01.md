# Chappy5 実機性能データベース収集ミッション v0.3

更新日: 2026-08-31

## 目的

5号機初期から2026年現在までの実在パチスロ機について、メーカー公式・公的資料・攻略/解析サイト等から確認できる**実機の性能事実データ**を広く収集する。

このフェーズでは分析・客AI・ホール経営評価・架空機化を行わない。

まず「実機には実際にどのような性能の台が存在したか」を後から再利用できる生データとして蓄積する。

## 収集年代

5号機初期から2026年現行機までを継続的に網羅する。

便宜上の年代タグ例:
- 5号機初期
- 5号機中期
- 5号機後期
- 5.5号機
- 5.9号機
- 6号機初期
- 6.1号機
- 6.2号機
- 6.4号機
- 6.5号機
- 6.6号機等
- スマスロ
- 2026年現行

厳密な規則区分と俗称/市場区分が異なる場合は混同せず記録する。

## 可変フィールド

機種ごとにゲーム性が違うため、上記に存在しない性能数値も収集してよい。

ただし、必ず「何を表す数値か」「単位」「出典」が分かる形で保存する。

無理に全機種を同じ項目へ押し込まない。

## 情報源優先順位

1. メーカー公式
2. 公的機関/業界一次資料
3. 信頼できる攻略・解析サイト
4. 複数攻略サイトの一致
5. 単一二次資料

古い5号機で公式情報が消失している場合は、当時の解析ページやアーカイブ等を利用してよい。

検索結果のスニペットだけで数値を確定せず、可能な限り元ページ本文を確認する。

## 信頼度

- OFFICIAL: メーカー/公的一次資料
- INDUSTRY: 業界一次資料
- ANALYSIS_HIGH: 複数の解析資料で一致
- ANALYSIS_SINGLE: 単一解析資料
- UNVERIFIED: 情報はあるが十分に確認できない
- CONFLICT: 情報源間で数値が一致しない

このフェーズではESTIMATED値を原則作らない。

## 絶対ルール

- 不明値を推測で埋めない。
- 計算で逆算できても、元データと計算値を区別する。
- 設定不明の値を勝手に設定別へ分解しない。
- サイト間で違う値は平均せずCONFLICTとして双方を残す。
- 「約」「最大」「平均」「期待値」を混同しない。
- 枚/G、G/50枚、確率、%等の単位を必ず残す。
- 設定L等の特殊設定を通常設定と混同しない。
- 同名シリーズ/後継機/別スペックを別機種として識別する。
- 解析値とメーカー公表値を混同しない。
- 出典URLと取得日を必ず保存する。

## 保存形式

最初はGitHub上のMarkdownを正本とする。

候補:
`docs/real_machine_db/INDEX.md`
`docs/real_machine_db/machines/*.md`

各機種ファイルは、共通フィールド + その方式固有の性能フィールド + Sourcesで構成する。

データ項目が安定して十分な件数が集まった段階で、JSON/CSV等の機械可読形式を別途生成する。

## 1機種ファイルの最低要件

```text
machineName:
manufacturer:
releaseDate:
generation:
medalSize:
smartSlot:
systemType:

settings:
payoutRateBySetting:
baseGamesPer50:

bonusData:
rtArtData:
atCzData:
smallRoleData:
technicalInterventionData:
ceilingAndModeData:
otherPublishedPerformanceData:

sources:
- url:
  sourceType:
  retrievedAt:

missingFields:
conflicts:
notes:
```

該当しない項目はN/A、調査しても確認できない項目はUNVERIFIEDとする。

## Chappy5 分担

5担当は「系統の評価者」ではなく、**収集範囲の分担者**とする。

1. 5号機前半担当
2. 5号機後半担当
3. 5.5/5.9〜6号機初期担当
4. 6号機中後期〜スマスロ/現行担当
5. QA・重複/出典/CONFLICT監査担当

担当境界で機種が漏れないようINDEXを共有する。

## 収集量

最初から代表18機種だけに限定しない。

まずフォーマット確認用に少数機種を収集し、問題がなければ5号機初期から順に拡大する。

中期目標: 100機種以上
長期目標: 可能な範囲で200機種以上

ただし件数より正確性を優先する。
