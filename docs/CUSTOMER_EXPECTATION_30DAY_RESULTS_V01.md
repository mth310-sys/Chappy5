# 客AI 多層期待記憶 30日シミュレーション結果 v0.1

更新日: 2026-08-31

目的: `CUSTOMER_EXPECTATION_MEMORY_30DAY_V01.md` の4層記憶（店舗・分類・島・曜日）を用い、営業方針P1〜P5を各5,000回、30営業日連続で簡易Monte Carlo試験した。

注意: これは構造検証用の暫定モデル。N-01設定配分別の単日基礎値を前段13時間試験から使用し、期待→来店/稼働の補正、日次ノイズ、記憶学習率を簡略化している。正式バランス値ではない。

## 1. 営業方針

- P1 常時回収: 30日すべてA低設定中心
- P2 週末還元: 月〜金A、土日C
- P3 バランス: B中間中心、土曜のみC
- P4 強日→翌日回収: 月〜金B、土曜D全台系、日曜A
- P5 不規則メリハリ: 基本A、30日中5日だけC。曜日固定なし

## 3. 最重要結果

### P1は最も粗利が大きいが、後半稼働が落ちる
P1は30日粗利約+42.1万円で最大。しかし前半15日アウト618,558に対し後半605,392へ約2.1%低下し、月末Store期待も-0.153。

現モデルでも「低設定なら永遠に同じ額を抜ける」にはならず、弱い公開結果の反復が将来稼働を削る方向が出た。

ただし30日程度ではまだP1の短期粗利優位が非常に大きい。経営ゲームとしては家賃・人件費・競合・機械代・長期常連流出まで接続して判断する必要がある。

### P2は黒字を残しながら週末期待を形成
P2は約+12.7万円の期待粗利を残し、P1より30日アウトが約5.8万多い。月末Store期待は-0.048まで改善。

曜日記憶は土日だけ明確にプラス方向へ分離した。
- 土曜 +0.114
- 日曜 +0.114
- 平日 約-0.085〜-0.099

つまり「週末は強い店」という営業癖を客AIが学習した。

### P3は稼働と信頼が育つが、現在のN-01経済値では赤字
P3は後半15日のアウトが前半より約8,200増加。月末Store期待+0.085。

ただし30日期待粗利は約-23.6万円。現状では中間中心営業の直接コストが高く、N-01島単独では回収できていない。

### P4では強日と翌日回収が完全に読まれた
P4の月末曜日期待:
- 土曜（D全台系） +0.259
- 日曜（A回収） -0.086

同じ店でも「土曜は狙う、日曜は避ける」が形成された。

これは狙い通り。ただしP4は約-26.0万円で、強日の投入量が大きすぎる。将来、他島波及・新規客獲得・競合からの奪取を入れた上で再評価する。

### P5は曜日固定営業と違う性格になった
P5は約+24.0万円の黒字。Store期待-0.079でP1より改善したが、曜日ごとの期待がP2ほど明確に分離しない。

つまり「週末が強い」ではなく、「弱い日が多いが時々当たりがある」という店の見え方になる。

この差はゲーム上の営業スタイルとして有用。

## 4. 30日試験から見える経営上のトレードオフ

少なくとも構造上、以下を同時最大化できない状態ができた。

- P1: 当月粗利最大、信頼低下
- P2: 黒字維持、週末ブランド形成
- P3: 稼働/信頼上昇、当月赤字
- P4: 強い曜日ブランド、翌日回収も読まれる、大赤字
- P5: P1より粗利を犠牲にしつつ不規則な期待を残す

これは「最高設定を入れ続ければ正解」「最低設定だけなら正解」という単純な一択を避ける基礎になる。

## 5. モデル上の不足

今回の結果を正式バランスへ採用してはいけない。特に以下が未実装。

- 客個体ごとの資金
- 滞在可能時間
- 持ちメダル
- 客ごとの設定推測精度
- 常連個体の離脱/復帰
- 競合店との店選択
- 他島への評判波及
- 新台/中古台の機種人気
- 家賃、人件費、設備費、機械購入費
- 非等価交換
- 厳密なgames→out変換
- 実績差枚からの売上/粗利逐次計算

また現試験では期待値が稼働母数へ簡易的な倍率として入る。最終実装では、期待は「来店候補の店選択」に使い、実アウトは個々の客の着席・続行から生成する。

## 6. 次の重要検証

次は競合店を導入する前に、客を集団倍率から最小限の個体へ落とす。

最小Customer状態候補:
- id
- regularity / 常連度
- bankroll / 当日予算
- availableMinutes / 滞在可能時間
- settingLiteracy / 設定推測力
- riskTolerance / 荒さ許容
- preferredCategory
- memoryConfidence
- currentMachineId
- heldCoins
- visitHistory

最初はNORMAL設定狙い型とライト型の2系統までに留める。

これにより、同じ公開データを見ても「粘る客」「やめる客」「そもそも来ない客」が生まれ、店舗期待を単純倍率でアウトへ変換する段階から脱却できる。

## 7. 暫定結論

30日モデルでは、営業方針の反復から客AIが曜日癖を学び、月後半の稼働にも影響する構造が確認できた。

特にP2とP4で曜日記憶が明確に分離したことは重要。

次段階ではこの記憶をCustomer個体へ持たせ、`期待 → 店選択 → 入店 → 台選択 → 遊技 → 記憶更新` の完全な客側ループへ移行する。
