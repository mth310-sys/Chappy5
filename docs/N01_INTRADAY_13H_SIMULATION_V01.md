# N-01 10台島 13時間時系列シミュレーション v0.1

更新日: 2026-08-31

目的: 10:00 OPEN → 23:00 CLOSE の営業を13個の1時間ブロックへ分解し、N-01 10台島について「結果が出る → 客が観測する → 続行/移動/退店する → 次の時間帯の稼働が変わる」という営業中の連鎖を定義する。

注意: N-01、客AI係数、時間帯来店量、各閾値はすべて検証用暫定値。正式採用ではない。

## 1. 時間モデル

営業時計:
- 10:00 OPEN
- 23:00 CLOSE
- 13時間

内部経営計算は1時間単位の13ブロックを基本とする。

画面描画はこの計算粒度から独立させる。客キャラクターの歩行・着席・離席は滑らかに補間してよいが、全台の経営計算を毎フレーム行わない。

## 2. 時間帯ごとの基礎来店係数（暫定）

| 時刻 | 基礎来店係数 | 想定 |
|---|---:|---|
| 10-11 | 0.85 | 朝一客 |
| 11-12 | 0.70 | 朝の落ち着き |
| 12-13 | 0.80 | 昼前後 |
| 13-14 | 0.95 | 午後流入 |
| 14-15 | 1.00 | 午後 |
| 15-16 | 1.00 | 午後 |
| 16-17 | 1.05 | 夕方前 |
| 17-18 | 1.20 | 仕事終わり流入開始 |
| 18-19 | 1.35 | 夕方ピーク |
| 19-20 | 1.40 | 夜ピーク |
| 20-21 | 1.25 | 夜 |
| 21-22 | 0.95 | 閉店時間を意識 |
| 22-23 | 0.55 | 新規着席減少 |

この係数は実ホールの確定統計ではなく、時系列AI検証用。将来、曜日・地域・客層・店舗人気で変える。

## 3. 1時間ブロックの処理順

各時間帯で以下を順番に処理する。

1. 来店候補数を決める
2. 店舗期待・島期待で実来店数を補正
3. 入店客が公開データから候補台を評価
4. 空き台へ着席、または打たずに退店
5. 着席中の各台でゲーム進行
6. BB/RB/小役/差枚を更新
7. 公開データを更新
8. 着席客が自台を再評価
9. 続行 / ヤメ / 台移動を判定
10. 空いた台を店内客・新規客が再評価
11. 島全体の見え方を更新
12. 次時間帯へ

重要: 設定番号は3, 6, 8, 11の客判断処理へ渡さない。

## 4. 台の真値と公開値

### MachineTruth
- setting
- theoreticalPayout
- bbProbability
- rbProbability
- internalRoleProfile
- baseCoinUnitProfile

### MachinePublicState
- gamesPlayed
- bbCount
- rbCount
- combinedProbabilityObserved
- playerNetCoins
- currentOccupancy
- lastVacatedAt

### CustomerBelief
- machineScore
- islandScore
- storeExpectation
- confidence
- currentCommitment

この3層を分離し、設定1誤爆・設定6不発をそのまま客の誤認へつなげる。

## 5. 1時間あたりゲーム進行

着席している台だけ gamesPlayed を増加させる。

初期検証ではノーマル機の1時間ゲーム数を固定値にせず、客ごとに `gamesPerHour` を持たせる。

暫定レンジ:
- ゆっくり: 550G/h
- 標準: 650G/h
- 速い: 750G/h

離席・台移動が時間途中に発生した場合は実遊技時間率を掛ける。

`hourGames = gamesPerHour × occupiedFraction`

アウトは gamesPlayed から別途換算し、gamesPlayed と out を混同しない。

## 6. BB/RB発生

各台の実設定に対応するN-01暫定BB/RB確率を使用する。

| 設定 | BB | RB |
|---:|---:|---:|
| 1 | 1/285 | 1/440 |
| 2 | 1/278 | 1/410 |
| 3 | 1/270 | 1/370 |
| 4 | 1/258 | 1/320 |
| 5 | 1/246 | 1/285 |
| 6 | 1/232 | 1/245 |

1時間ごとの当選回数は確定回数を割り当てず確率試行する。したがって設定6でも午前中ノーボーナス、設定1でも短時間でBB/RB連打が発生可能。

## 7. 客の再評価タイミング

1時間終了時だけ全員一斉に判断すると不自然なので、実装時は客ごとに判断タイミングをずらす。

v0.1の論理単位では以下を使う。
- 入店時
- 着席後およそ250〜500Gごと
- ボーナス後
- 大きな差枚変化後
- 隣接台が空いた時

描画上は1時間ブロック内にイベント時刻を散らす。

## 8. 続行スコア（暫定）

客は次の観測から続行価値を作る。

`continueScore = selfEvidence + islandEvidence + storeExpectation + sunkCommitment - fatigue - closingPenalty`

selfEvidence候補:
- RBの強さ
- BB/RB合算
- サンプルG数
- 現在差枚

重要: 差枚だけで設定判別させない。N-01ではRBをBBより設定推測上やや重くする。

confidenceはgamesPlayedが少ないほど低くする。朝100GでRB1回の台と、4000GでRBが強い台を同じ確信度にしない。

## 9. 島の見え方

島スコアは平均設定ではなく公開結果から計算する。

候補入力:
- プラス差枚台数
- 強いRB挙動台数
- 高サンプルで合算が良い台数
- 稼働台数
- 明確な好挙動台の最大強度

これによりメリハリ配分では、設定6が発見された時に設定1を含む周辺台へ探索稼働が波及できる。

## 10. 台移動

現在台のcontinueScoreが低く、かつ空き台により高いmachineScoreがある場合に移動候補とする。

移動コストを設ける。
- 今の台への投資G数
- 持ちメダル状態
- 空き台のサンプル不足
- 閉店までの残り時間

したがって少し良さそうな台が空いただけで全員が瞬間移動しない。

## 11. 閉店ペナルティ

21時以降は新規着席と続行判断へclosingPenaltyを加える。

特に22時以降は、ノーマル機でも「残り時間が短いから今から未知の台を打たない」という判断を増やす。

将来AT機では残り時間リスクをノーマルより強くできる。

## 12. 営業中に発生させたい代表現象

### ケースA: 設定6の朝不発
10時台: 6がボーナスを引けない
→ 朝客が弱いと判断して離席
→ 昼に別客が着席
→ RBが付き始める
→ 夕方にサンプルが育つ
→ 周辺客が島を再評価
→ 夜に島稼働が上がる

### ケースB: 設定1の誤爆
10〜12時: BB/RBが上振れる
→ 高設定候補として粘られる
→ 周辺の探索稼働も増える
→ 夕方から数値が悪化
→ 客が順次離脱

### ケースC: メリハリ発見
設定6が2台とも午後まで好挙動
→ islandScore上昇
→ 空き低設定にも「残りの当たり台探し」の客が座る
→ 高設定そのもの以外のアウトも上がる

### ケースD: 低設定島の失速
朝の偶然で数台動く
→ 高サンプルになるにつれRB/合算が弱く見える
→ 移動先にも強い台がない
→ islandScore低下
→ 夕方ピーク時間でも他島/退店へ流れる

## 13. 翌日への記憶

閉店時に客集団の観測結果からstoreExpectationを更新する。

設定番号の答え合わせは客には行わない。

更新材料:
- 島の公開結果
- 強い挙動台が何台見えたか
- 自分が遊技した結果
- 店全体の稼働感
- 過去数日の期待

単日結果だけで評判が完全反転しないよう指数移動平均型の記憶を候補とする。

例:
`nextExpectation = oldExpectation * 0.75 + todayObservedStrength * 0.25`

係数0.75/0.25は暫定。

## 14. iPhone実装上の方針

経営エンジン:
- 13時間ブロック + ブロック内イベント
- 非表示客は数値集約可能
- 全客を毎フレームAI判断させない

表示:
- 画面内客のみ詳細アニメーション
- offscreen客は状態だけ保持
- カメラ移動で表示対象になったら状態から描画復元

これにより将来200〜300台規模へ拡張しても、経営計算と描画負荷を分離できる。

## 15. 次の検証

このv0.1を使い、A低設定中心 / B中間中心 / Cメリハリ / D全台系をそれぞれ多数営業日シミュレーションする。

記録する指標:
- 時間別来店数
- 時間別着席台数
- 台別gamesPlayed
- 台別out
- BB/RB
- 客側差枚
- 台移動回数
- 退店数
- 島スコア推移
- 島売上
- 島粗利
- 閉店時storeExpectation

最重要確認点は「設定配分の違いが、固定アウトを与えなくても時間経過の中から異なる稼働曲線として自然に現れるか」。
