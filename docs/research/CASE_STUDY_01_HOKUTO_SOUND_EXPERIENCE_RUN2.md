## 2. `REST AUDIO` — 通常時の価値は「静か」ではなく予測可能であること

### SOURCED FACT
- 通常時の演出は基本的にレバーONで発生するが、リール始動時に発生するとチャンスという違和感法則が存在する。
- 「遅れ」は中段チェリーに期待できるCueとして扱われる。
- 演出発生のSTOPタイミング自体が法則になり、第1→第3停止、いきなり第2停止、いきなり第3停止などが強い意味を持つ。
- リール全消灯はレバーON、リール始動、第1〜3停止、第3停止離し等、発生タイミングごとに極めて希少な本前兆濃厚演出として成立する。

### INTERPRETATION
違和感Cueは単体音の強さでは成立しない。プレイヤーが数十〜数百Gで身体的に覚えた `NORMAL TIMING` が先にある。

`BET → LEVER → REEL START → STOP1 → STOP2 → STOP3 → RELEASE → RESULT`

この順序へAudio/Visualの反応位置が安定しているため、発火が1段ずれる、遅れる、消える、別タイミングへ移るだけで情報になる。

### REUSABLE PRINCIPLE — `REST AUDIO`
通常音響の第一目的は派手さではなく「基準座標を身体へ学習させること」。

強Cueを作る前に、
- いつ鳴るか
- 何もないGでは何が鳴らないか
- STOP音と演出音がどう分離するか
- 次BETまでの空白がどこにあるか

を固定する。

## 3. `AUDIO DEVIATION AXES` — 強さは音量だけではない

北斗で確認できる強い偏差は、少なくとも以下に分類できる。

1. `ADD` — 通常にはない音/ボイス/楽曲が加わる。
2. `DELAY` — 期待した音・演出の発火が遅れる。
3. `OMIT` — 普段ある反応が欠落/消灯する。
4. `RELOCATE` — レバーONのはずがリール始動、第3停止等へ移る。
5. `CONTRADICT` — 音が作った対応役候補を後続Visual/Reelが否定する。
6. `SUSTAIN` — BGMそのものが次セット保証等の状態情報として持続する。

### REUSABLE PRINCIPLE
`強い = louder` を禁止する。希少性・タイミング・欠落・矛盾・持続のどれで注意を取るかを先に決める。

## 4. 音は「候補集合」を先に作れる

### SOURCED FACT
ラオウステージのギター音は足跡発見演出またはスイカ/チェリー対応。後続演出が対応関係から矛盾すると本前兆濃厚となる。

### INTERPRETATION
音がまず答えを告知するのではなく、`この後どこを見るか` を指定している。

プレイヤー体験：
`音を認識 → 対応役/演出候補を想起 → STOP/リール/液晶を観察 → 一致か矛盾かを判定`

### REUSABLE PRINCIPLE — `AUDIO AS QUESTION`
Sound Cueには「答え」だけでなく「問い」を担わせられる。耳が先に候補を作り、手と目で答えを見る構造は、3STOPを自然に情報体験へできる。

---

## 5. STOPはAudioの句読点であり、希少な同期点

### SOURCED FACT
- 通常時にはSTOP別の演出法則が存在する。
- BBバトル中、レア役成立時に第3停止をねじることで「ねじり音」が発生する場合があり、発生時は当該レア役で1段階以上の恩恵獲得を示す。
- 初代モードではねじり音は基本的に発生せず、発生した場合は非常に強い上位示唆になると攻略資料で説明される。

### INTERPRETATION
毎回STOPに派手SEを重ねるのではなく、普段のSTOP入力を低密度に保つことで、特定GだけSTOP保持/離しと音が結合した時に身体的な意味が生じる。

Visual Run 2の `SYNC SCARCITY` と一致する。

### REUSABLE PRINCIPLE — `INPUT-AUDIO CONTRACT`
- 毎G入力：短い・予測可能・低疲労。
- 希少入力状態：入力タイミングそのものへ情報を載せる。
- 同一CueをLEVER/BET/STOPへ無差別に割り当てない。

---

## 6. BB入口は「1発のファンファーレ」ではなく段階的な状態確定

### SOURCED FACT
- BB告知後は準備中を経由し、「狙え」演出から赤7/北斗図柄を揃えてBB開始。
- 狙え演出の発生タイミングが通常と異なる場合、停止結果に関する別法則が存在する。
- 揃う図柄や停止ラインに継続率示唆が存在する。

### INTERPRETATION
入口の体験は
`本前兆読解 → 告知 → 準備 → 狙え → 停止形確認 → 継続率期待形成 → BB開始`
と複数段階。

Soundはここで一回だけ最大音を鳴らせばよいのではなく、各段階の責務を分ける必要がある。

### REUSABLE PRINCIPLE — `ENTRY STAIRS`
Reward Entryは `NOTICE / CONFIRM / PARTICIPATE / START` に分ける。告知された後にもプレイヤーのSTOP操作で報酬へ入る余白を残せる。

---

## 7. BBのSUSTAINは「毎セット最大刺激」ではない

### SOURCED FACT
- バトルパート開始時にBGMが変化するとセット継続確定。
- 通常モードでは5セット目以降、継続時の約1/3でBGM変化が発生する。
- 楽曲ごとに発生可能セット数が異なる。
- 20セット目以降ではラオウ昇天が発生しなかった時点で継続濃厚となり、BGMが毎セット変化する仕様。
- 初代カスタムではBGM変化種類・開始条件が減り、発生タイミングも通常モードのレバーONからBETへ移る。

### INTERPRETATION
BGM変化は単なる「盛り上げ曲解禁」ではなく、`今セットは続く` というゲーム情報を長い音として保持する。

一方、序盤から毎セット楽曲を変えない。5セット目以降かつ一部という希少性があるため、変化自体が報酬になる。

### REUSABLE PRINCIPLE — `BGM AS STATE MEMORY`
BGMは雰囲気だけでなく、その区間で既に獲得した保証/状態をプレイヤーが忘れないための持続UIにできる。

### REUSABLE PRINCIPLE — `ENTRY IMPACT != SUSTAIN DENSITY`
突入時の高刺激と、30分以上続く区間の刺激密度は別設計にする。

---

## 8. `INPUT TIMING CAN CARRY RULES` — BETとLEVERの違い

### SOURCED FACT
- 通常モードではバトルパート開始時のBGM変化がレバーON側で発生する。
- 初代モードでは同じ種のBGM変化がBETでのラウンド表示時へ移る。
- 敗北後の復活は基本MAX BETで発生するが、リプレイ等の条件ではLEVER復活があり、特定条件でLEVER復活した場合はバトル中の成立役による継続書き換えが確定する。

### INTERPRETATION
プレイヤーは「何が鳴ったか」だけでなく、`どの身体入力に対して鳴ったか` から内部過程を読む。

### REUSABLE PRINCIPLE
Audio仕様にはCue名だけでなく必ず `TRIGGER INPUT / GAME STATE / TIMING / GUARANTEE / PRIORITY` を持たせる。

---

## 9. 初代カスタムは「音を減らしてもゲームが残る」実証

### SOURCED FACT
初代カスタムでは通常時の演出頻度が大幅減少し、AT中も宿命バトル/Vストックの見た目上の可視化、ベル入賞表示、一部チャンスアップ、BGM変化種類等が削られる。一方、内部抽選は継続する。

### INTERPRETATION
これはAudio/Visual密度を減らしても、
- リール
- モード
- レア役
- BB継続
というゲーム骨格が成立している証拠。

### REUSABLE PRINCIPLE — `PRESENTATION SUBTRACTION TEST`
将来のChappy5候補では、演出Cueを半分近く削った仮想状態でも通常→当たり→継続が読めるかをQAする。

削ると遊技自体が成立しなくなるなら、Sound/Visualがゲーム骨格の代用品になっている可能性がある。

## 10. memorable と fatiguing を分けるための現時点モデル

### SOURCED / OBSERVED SUPPORT
- BGM変化は一定セット以降かつ一部に制限され、頻発させていない。
- ねじり音・全消灯・タイミング違和感等は希少発生である。
- 初代カスタムでは情報密度そのものを下げられる。
- 設定5実戦レポートでも、通常時は設定看破をしながら、中段チェリーを待ち、BBに入ると継続を願うという注意対象の切替が語られている。

### INTERPRETATION
記憶に残るCueは、波形そのものより
`低い基礎密度 × 希少発生 × 明確なゲーム上の意味 × 入力同期 × 報酬` 
の積で強くなる。

疲労するCueは
`高頻度 × 毎回大音量 × 意味が弱い × 回避不能 × 長い`
で増幅する。

### UNRESOLVED
実際の音圧と疲労は原音長尺を直接聴取/測定していないため、北斗がどの周波数帯・dB・定位で疲労を避けているかは未確定。

## 11. Audio hierarchy model extracted from Hokuto

北斗から抽象化できる音響階層：

1. `BASE OPERATION` — BET / LEVER / REEL / STOP / RESULTの身体同期。
2. `ATTENTION CUE` — レア役候補、遅れ、声、局所SE。
3. `LAW CUE` — 後続出目/Visualとの対応・矛盾を読むCue。
4. `STATE CUE` — モード/前兆/継続期待を示す持続・反復情報。
5. `REWARD ENTRY` — 告知→準備→狙え→開始の段階音響。
6. `SUSTAIN BGM` — 継続区間の長時間背景。
7. `GUARANTEE CHANGE` — BGM変化など、獲得済み保証を保持する音。
8. `PHYSICAL EXCEPTION` — PUSH/振動等の希少身体フィードバック。

重要：すべてを同時に最大化しない。

## 12. Cross-specialty integration

### Game & Reelとの接続
Game側Run 2で、抽選/状態更新/結果提示タイミングを分離すべきと確認。Soundも同じく `TRIGGER / INFORMATION AGE / PRESENTATION TIME` を別管理する必要がある。

### Visual & Mechanismとの接続
Visual側Run 2の
- `REST VISUAL`
- `SYNC SCARCITY`
- `INPUT RARITY MUST MATCH FEEDBACK RARITY`
- `BODY GRAMMAR STABILITY`
とSoundの
- `REST AUDIO`
- `AUDIO DEVIATION AXES`
- `INPUT-AUDIO CONTRACT`
が一対一で対応する。

### Playtest & QAとの接続
- `ATTENTION COMPRESSION`: 音も「何を聞かなくてよいか」を学べる必要がある。
- `ENTRY IMPACT != SUSTAIN QUALITY`: BGM/SE密度を入口と長時間で分ける。
- `UPPER ABSENCE TEST`: 上位専用強音がなくても通常BBを再度引きたいか。
- `RETURN ACCEPTANCE`: 長連後に通常REST Audioへ戻った時、それを罰として感じないか。

## 14. Run 2 reusable principles summary

- `REST AUDIO BEFORE SIGNATURE SOUND`
- `AUDIO DEVIATION ≠ VOLUME ONLY`
- `AUDIO AS QUESTION`
- `INPUT-AUDIO CONTRACT`
- `ENTRY STAIRS`
- `BGM AS STATE MEMORY`
- `ENTRY IMPACT != SUSTAIN DENSITY`
- `PRESENTATION SUBTRACTION TEST`
- `MEMORABLE = SCARCITY × MEANING × SYNCHRONY × REWARD`

これらは第三者の固有音をコピーするための規則ではなく、将来オリジナル台で「なぜその音が鳴るのか」を説明可能にするための抽象原則。
