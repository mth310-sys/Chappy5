## Central finding

Run 8 resolves the ambiguity left by Sound Run 7 and QA Run 7:

**quiet behavior after an event is not sufficient proof that responsibility actually closed.**

A player may stop checking because:
1. the old duty genuinely resolved;
2. the player disengaged from the signal channel;
3. strategic monitoring ended but the old cue/action relation remains latent and can reappear later.

Therefore:

`CLOSURE INTEGRITY = BASELINE RECOVERY + OBSOLETE-DUTY SUPPRESSION + PRESERVED VALID-CUE DISCRIMINATION`

Short rules:

`CLOSURE IS PROVEN BY SELECTIVITY, NOT BY SILENCE.`

`HEALTHY RELEASE PRESERVES THE ABILITY TO REOPEN.`

## QA classification added

A later authorized Human trial should distinguish:

- `GENUINE RELEASE`: routine recovers, old duty stays retired, later valid cue still reopens attention.
- `LINGERING VIGILANCE`: valid cues detected, but checking/waiting remains elevated.
- `FALSE CALM / DISENGAGEMENT`: checking falls, but later valid-cue detection falls too.
- `LATENT OLD DUTY`: ordinary pace looks normal, but an obsolete cue/action relation later reactivates.
- `GLOBAL OVER-CLOSURE`: one local duty ending is mistaken for the whole machine becoming safe-to-ignore.
- `NEVER-CLOSED AMBIGUITY`: behavior normalizes only because time/effects stopped, with no legible completion evidence.

## Main reusable principles

- `CLOSURE IS PROVEN BY SELECTIVITY, NOT BY SILENCE.`
- `HEALTHY RELEASE PRESERVES THE ABILITY TO REOPEN.`
- `NO MONITORING COST DOES NOT GUARANTEE COMPLETE DEACTIVATION.`
- `ROUTINE PACE RECOVERY IS NECESSARY EVIDENCE OF RELEASE, NOT SUFFICIENT EVIDENCE.`
- `CLOSURE IS DUTY-SPECIFIC; TEST THE RETIRED CUE–ACTION LINK, NOT A GLOBAL FEELING OF CALM.`
- `A DUTY THAT ENDS BY BEING RESOLVED IS EASIER TO TRUST THAN A DUTY THAT SIMPLY DISAPPEARS.`
- `LONG-SESSION CLOSURE QA MUST TEST BOTH OMISSION AND COMMISSION.`
- `LOW FALSE ALARMS WITHOUT PRESERVED HITS CAN BE DISENGAGEMENT.`
- `HIGH HITS WITHOUT LOW BASELINE COST CAN BE VIGILANCE.`
- `A TEST OF DEACTIVATION CAN REACTIVATE WHAT IT IS TRYING TO MEASURE.`
- `FATIGUE QA MUST ASK WHAT THE PLAYER FAILS TO NOTICE AND WHAT THEY FAIL TO STOP NOTICING.`
