Question received from Visual & Mechanism Run 4:

**What auditory evidence makes Human hear a STOP as one causal chain—input accepted → reel/mechanism responds → reel settles—without turning every STOP into a loud effect, and how can platform latency/dropout be prevented from sounding like legitimate machine timing variation?**

## Key change

Add **auditory causal-chain ownership** and **competing platform timing source** to the existing Sound model.

Research-only chain:

`PLAYER ACTION`
→ `LOCAL ACCEPTANCE EVIDENCE`
→ `REEL / MECHANISM STATE CHANGE`
→ `SETTLING / RESOLUTION EVIDENCE`
→ `PARTIAL MACHINE STATE PRESERVED FOR NEXT STOP`

The Sound task is not to make every stage audible. It is to ensure that audio which is present agrees with one stable causal history.

## Main principles

- `AUDITORY OWNERSHIP IS A SEQUENCE CLAIM, NOT A SINGLE-ONSET CLAIM.`
- `THE EARLIEST PLAUSIBLE EFFECT CAN STEAL CAUSAL OWNERSHIP FROM A LATER ONE.`
- `ADAPTATION TO LATENCY IS NOT A RESPONSIVENESS PASS.`
- `CROSS-MODAL SUPPORT SHOULD REINFORCE CAUSAL ORDER, NOT LAUNDER LATE AUDIO.`
- `PLATFORM LATENCY IS A COMPETING CAUSAL SOURCE, NOT A VALID MACHINE-TIMING VARIANT.`
- `A TIMING DEVIATION CAN CARRY GAME MEANING ONLY AGAINST A PLATFORM-ROBUST BASELINE.`
- `ONE STOP SHOULD LEAVE ONE COHERENT CAUSAL AUDITORY HISTORY.`
- `STOP1 / STOP2 AUDIO MUST NOT ERASE THE PARTIAL-STATE LISTENING SPACE NEEDED FOR THE NEXT REEL.`
- `WHEN CONTINUITY IS SEMANTIC, TECHNICAL DROPOUT IS FALSE GAME INFORMATION.`
- `CAUSAL CLARITY DOES NOT REQUIRE MAXIMUM SALIENCE.`
- `ROUTINE STOP FEEDBACK SHOULD CONFIRM OWNERSHIP MORE OFTEN THAN IT DEMANDS ORIENTING.`

## Evidence delta

External research used in this run supports:

- a prior additional sound can inhibit intentional binding between an action and a later target sound;
- repeated exposure to delayed auditory feedback can shift the decision criterion for self-agency without improving perceptual sensitivity;
- Web Audio latency contains browser/host/device components that are not fully controlled by an authored game timing rule;
- browser `latencyHint` is a request, not a guarantee, while `baseLatency` and `outputLatency` expose only parts/estimates of the output path.

Experimental delay values are not converted into pachislot production thresholds.
