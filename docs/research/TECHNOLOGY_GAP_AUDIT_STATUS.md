## Human directive
After the current study cycle, each fixed Director must compare accumulated real-machine/app learning against Chappy5/遊創舎's actual capabilities and answer whether anything else must be learned before production readiness is considered.

This audit does **not** return to original concepts. `SIGNAL/FORGE/VAULT` remain frozen and unranked.

## Required classification
Every claimed gap must be classified as one of:
- `LEARNED` — sufficiently understood; no additional study required now.
- `KNOWLEDGE GAP` — real-machine/product knowledge remains insufficient.
- `TECHNOLOGY GAP` — understood in principle but Chappy5/遊創舎 cannot yet reproduce/implement/validate it adequately.
- `MEASUREMENT GAP` — capability may exist, but there is no reliable measurement or PASS method.
- `PLATFORM GAP` — browser/iPhone constraints change the experience and require translation-specific capability.

For each item record:
1. capability already held;
2. lesson understood but not implemented/verified;
3. missing knowledge;
4. whether acquisition is possible in current GitHub + browser + iPhone workflow;
5. priority/value of learning it;
6. objective evidence required to mark it acquired.

## Fixed Director order
1. Machine Director — audit framework/integration only; do not pre-answer specialist domains.
2. Game & Reel Director — reel/control/state/math/input and real→phone translation gaps.
3. Visual & Mechanism Director — depth/material/light/reel/cabinet/action-geography/mobile rendering gaps.
4. Sound & Experience Director — timing/mix/body/latency/device-output/fatigue/audio-state gaps.
5. Playtest & QA Director — Human evidence, latency, ergonomics, long-session, interruption, device performance and experience-measurement gaps.
6. Next Machine Director — integrate all five and decide what additional study is actually justified.

## Machine framing from accumulated studies
The current evidence already shows that a browser machine needs more than functional parity. Production readiness eventually requires evidence for:
- internal game/reel law;
- repeated action ownership;
- physical/sensory presence translated to screen;
- causal timing across Game/Reel/Visual/Mechanism/Audio;
- REST and attention hierarchy;
- long-session engagement/fatigue;
- real-device behavior on iPhone;
- Human-in-the-loop evidence beyond automated Browser Test.

These are audit questions, not presumed deficiencies. Specialists must compare them against actual repository/遊創舎 assets before labeling a gap.
