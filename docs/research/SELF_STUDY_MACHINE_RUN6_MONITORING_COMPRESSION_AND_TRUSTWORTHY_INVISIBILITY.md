## Question received from Playtest & QA Run 6

How should the Machine-level Attention Contract incorporate `MONITORING COMPRESSION` so repeated play can become safely less monitored while preserving selective sensitivity to meaningful deviation, and how can this be distinguished from fatigue/desensitization without creating a constant alert system?

## Evidence inherited from the fixed-five study chain

Playtest & QA Run 6 establishes the behavioral distinction:

`LESS CHECKING != LOWER MONITORING COST.`

Healthy auditory/attention offloading requires convergence among reduced routine re-checking, preserved primary-task accuracy, preserved meaningful-deviation detection, controlled normal-event false alarms, coherent causal attribution and absence of compensatory slowdown/waiting/double-checking.

Machine Run 5 already separates:

`CAUSAL TRUST` = learned stable action/machine/state/resolution relations whose prediction errors remain diagnostic.

from

`LEARNED TOLERANCE` = widened acceptance or compensation around an unreliable relation without improved source discrimination.

Game/Reel Run 5 adds that mastery should shrink the live hypothesis set rather than merely increase play speed. Visual Run 5 treats stopped reels as external evidence/memory surfaces. Sound Run 5 treats useful routine audio as a way to save a glance rather than earn one.

## Machine integration — Monitoring Compression

Define:

`MONITORING COMPRESSION`
= repeated play reduces the number, duration and channel-switch cost of routine checks because stable machine law allows the player to predict what does not require active verification, while meaningful deviations remain selectively detectable and attributable.

This is different from simple habituation.

Healthy compression changes the monitoring policy from:

`CHECK EVERYTHING → VERIFY ROUTINE → VERIFY AGAIN → ACT`

toward:

`TRUST STABLE ROUTINE → ACT → ORIENT ONLY WHEN A LEGITIMATE DEVIATION OPENS A QUESTION → RESOLVE → RELEASE`

The machine therefore earns periods in which it can become perceptually quiet without becoming causally ambiguous.

## Trustworthy invisibility vs ignored unreliability

### TRUSTWORTHY INVISIBILITY

A routine system becomes less consciously monitored because:
- ordinary input acknowledgement is stable;
- action-effect timing remains coherent enough to support prediction;
- the player can safely leave redundant confirmation unattended;
- primary evidence remains available when needed;
- a meaningful deviation can still interrupt routine selectively;
- the deviation's source can be attributed;
- responsibility closes clearly and monitoring returns to REST.

### IGNORED UNRELIABILITY

A system becomes less consciously monitored because:
- repeated anomalies have become unsurprising;
- the player has stopped expecting precise confirmation;
- fatigue suppresses detection;
- normal and abnormal events are poorly discriminated;
- the player slows, waits or double-checks to compensate;
- the player abandons a channel because it is not worth trusting;
- good outcomes retrospectively mask weak causal ownership.

These two states can look similar if QA observes only check frequency or session smoothness.

## Attention Contract Run 6

Previous model:

`STABLE BASELINE → CLAIM OPENER → RESPONSIBILITY → SOURCE AUTHORITY → CROSS-CHANNEL SUPPORT → RESOLUTION → RELEASE → TRUST UPDATE → LOW-MONITORING REST`

Run 6 makes monitoring demand explicit:

`STABLE BASELINE → MONITORING COMPRESSION → LEGITIMATE DEVIATION → RESPONSIBILITY EXPANSION → SOURCE AUTHORITY → EVIDENCE ACCUMULATION → RESOLUTION → MONITORING RELEASE → TRUST UPDATE → LOW-MONITORING REST`

### MONITORING COMPRESSION
Routine competence should allow fewer active checks without reducing discrimination.

### LEGITIMATE DEVIATION
A change earns attention because it violates a trusted ordinary expectation or changes player responsibility. Novelty alone is insufficient.

### RESPONSIBILITY EXPANSION
Monitoring demand may temporarily rise when the machine asks for aiming, interpretation, choice, state confirmation or another real task.

### EVIDENCE ACCUMULATION
Visual/reel/audio/mechanism evidence should reduce uncertainty rather than create parallel mandatory checks.

### MONITORING RELEASE
Once the question is resolved, the machine must stop demanding vigilance. A presentation tail that continues to demand confirmation after knowledge is complete creates attention debt.

### TRUST UPDATE
Successful cycles should improve prediction and source discrimination, not merely increase tolerance for ambiguity.

## Monitoring demand should breathe

Repeated play should not target minimum attention at every instant. It needs a controlled duty cycle:

`LOW-DUTY REST → TEMPORARY HIGHER-DUTY QUESTION → RESOLUTION → LOW-DUTY REST`

This preserves two truths simultaneously:
- sparse/quiet routine can remain playable because the player knows what can be ignored;
- meaningful deviation can remain meaningful because ordinary monitoring is not permanently saturated.

Therefore:

`LOW MONITORING IS A REWARD OF STABILITY, NOT A DEFAULT ABSENCE OF FEEDBACK.`

and

`HIGH MONITORING SHOULD BE TEMPORARY AND RESPONSIBILITY-BOUND.`

## Cross-case reality anchor

Case Study 01 北斗 and Case Study 02 新ハナビ remain deliberately different anchors.

In 北斗-like state/progression play, monitoring can compress when ordinary state/presentation grammar is trusted, then expand around meaningful state evidence, battle/judgement or post-end questions.

In 新ハナビ-like reel-centered play, monitoring can compress as aiming/role-handling becomes motor routine, while partial stops, contradictions, timing deviations and temporary technical-intervention responsibilities selectively reopen attention.

The shared principle is not a progression formula or reel formula:

`MASTERY INCLUDES LEARNING WHEN THE MACHINE DOES NOT NEED TO BE WATCHED CLOSELY.`

No protected machine-specific design, stop-control table, sound, visual or mechanism is imported.

## Machine-level failure signatures for future authorized QA

Do not pass Monitoring Compression if reduced checking co-occurs with any of:
- lower meaningful-deviation detection;
- higher normal-event false alarms;
- lower reel/primary-task interpretation accuracy;
- ambiguous source attribution;
- slower input pace caused by waiting for confirmation;
- repeated double-checking moved to another channel;
- abandonment of an unreliable cue;
- fatigue-related misses mistaken for comfort.

A future Human trial should therefore seek converging evidence rather than a single monitoring metric.

## New cross-Director principles

- `MONITORING COMPRESSION = FEWER NECESSARY CHECKS AT PRESERVED DISCRIMINATION.`
- `TRUSTWORTHY INVISIBILITY IS EARNED; IGNORED UNRELIABILITY IS ABANDONMENT.`
- `THE MACHINE SHOULD BECOME QUIET THROUGH PREDICTABILITY, NOT THROUGH PLAYER RESIGNATION.`
- `A MEANINGFUL DEVIATION SHOULD REOPEN ATTENTION WITHOUT MAKING THE PLAYER MONITOR FOR DEVIATIONS CONSTANTLY.`
- `RESPONSIBILITY EXPANSION SHOULD RAISE MONITORING DEMAND; RESOLUTION SHOULD LOWER IT.`
- `PARALLEL CONFIRMATION CHANNELS ARE NOT FREE; IF BOTH MUST BE CHECKED, OFFLOADING HAS FAILED.`
- `THE BEST ROUTINE FEEDBACK CAN DISAPPEAR FROM CONSCIOUS ATTENTION WHILE REMAINING CAUSALLY RELIABLE.`
- `PRESERVED DISCRIMINATION IS THE PRICE OF ATTENTION RELEASE.`
- `LOW-MONITORING REST IS A MACHINE PROPERTY ONLY WHEN THE PLAYER CAN STILL DETECT AND ATTRIBUTE LEGITIMATE CHANGE.`
- `FATIGUE, HABITUATION AND MASTERY CAN ALL REDUCE OVERT CHECKING; ONLY MASTERY SHOULD IMPROVE OR PRESERVE SELECTIVE PREDICTION.`
