## Retained findings

The real cabinet's visual/mechanical contract depends on more than its graphics:
- human-scale silhouette;
- physical depth/material separation;
- dedicated recessed reel work surface;
- tactile lever/MAX BET/3 STOP body map;
- one machine-owned visual authority.

The phone translation replaces those with:
- flat machine context;
- finite pixel allocation;
- touch hit targets;
- manual/assist ownership of STOP responsibility;
- machine UI plus 777Real service UI.

Important distinctions:

`STRUCTURAL IMAGE FIDELITY ≠ PHYSICAL PRESENCE FIDELITY`

`REEL IMAGE FIDELITY ≠ REEL TASK FIDELITY`

`VISUAL BUTTON MAP ≠ TOUCH HIT MAP`

`HALL PRESENCE ≠ PERSONAL-SCREEN PRESENCE`

## Reusable principles added

`DIGITAL CABINET FIDELITY SHOULD BE JUDGED BY PRESERVED RELATIONSHIPS, NOT BY HOW MUCH OF THE ORIGINAL SHELL IS DRAWN.`

`FLATTENING CAN PRESERVE STRUCTURE WHILE DESTROYING MATERIAL PRESENCE.`

`PIXEL SHARE IS A GAMEPLAY RESOURCE WHEN THE PLAYER MUST READ OR AIM.`

`TOUCH TARGET FIDELITY AND VISUAL BUTTON FIDELITY ARE SEPARATE AXES.`

`WHEN ALL SURFACES BECOME ONE SCREEN, ATTENTION HIERARCHY MUST REPLACE MATERIAL HIERARCHY.`

`A WRAPPER UI SHOULD NOT BECOME A SECOND MACHINE COMPETING FOR THE SAME ATTENTION MOMENT.`

`A FAITHFUL TRANSITION IS INCOMPLETE IF THE PLAYER RETURNS TO THE RIGHT STATE BUT NOT TO THE RIGHT VISUAL ORIENTATION.`

`SCREEN IMMERSION IS NOT CABINET PRESENCE.`

## Important unresolved items

No controlled installed-app observation was available in this run. Keep unresolved:
- exact portrait/landscape behavior;
- practical current-iPhone machine viewport size;
- reel pixel dimensions and readable symbol threshold;
- exact STOP hit-target geometry;
- zoom/enlarge support for this exact app;
- service-overlay persistence/configuration;
- exact cabinet lamp/depth/material rendering retained in app;
- motion scaling/frame pacing;
- haptic substitution.

App Store review complaints about image quality/crashes remain QA leads only, not implementation proof.
