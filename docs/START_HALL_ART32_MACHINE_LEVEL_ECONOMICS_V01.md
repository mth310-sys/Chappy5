## 4. 理論値から見える重要点

この20台は「低設定中心」でも、設定2以上が必ずしもホール黒字ではない。

- スパイダーマン2設定2は99.8%でほぼ均衡
- 設定3は102.8%、設定4は107.3%で理論上客側
- リングにかけろ1は設定2から100.5%、設定3 103.0%

したがってA+RTへ設定を使う戦略は、単純な設定台数ではなく **どの機種のどの設定へ何OUT入るか** が粗利を大きく左右する。

## 5. 個体粗利式

台iについて:

```text
expectedSafe_i = actualOut_i × payoutRate(setting_i)
expectedHallDifference_i = actualOut_i - expectedSafe_i
expectedMachineGross_i = expectedHallDifference_i × 20円
```

例: スパイダーマン2設定4に5,000 OUT入った場合:

```text
expectedSafe = 5,000 × 1.073 = 5,365
hallDifference = -365枚
expectedMachineGross = -7,300円
```

同じ5,000 OUTでも設定1なら:

```text
expectedSafe = 5,000 × 0.967 = 4,835
hallDifference = +165枚
expectedMachineGross = +3,300円
```

設定変更による利益差が台単位で明確になる。

## 6. OUTは機械割から生成しない

機械割が高いから自動的にOUTが増える設計にはしない。

Day 2のOUTは:

```text
客の来店
→ 前日machine/category/hall memory
→ 着席
→ 実際の当選履歴
→ 継続/離席
→ actualOut
```

で生成する。

機械割は主に出玉側へ効き、その出玉が客に観測されて後続稼働へ間接的に返る。

## 7. ボーナス確率を観測信号へ使う

設定別ボーナス確率も客AIの観測材料へ接続する。

ゲーム内部では例えば1時間ごとに:

```text
playedGames
→ bonus lottery
→ visible BIG/MID count
→ customer inference
```

を更新する。

高設定でも短時間不発は起こるため、理論確率をそのまま表示履歴にはしない。

## 8. 技術介入

両機にはRTパンク回避など技術介入要素がある。

将来:

```text
actualPayout
= theoreticalPayout
+ playerSkillAdjustment
```

を導入する。

上手い客は理論値へ近づき、初心者は取りこぼし・RTパンクで下振れしやすい。

これにより客タイプがホール粗利へ直接影響する。

ただしv0.1では技術介入補正を0として、まず設定別理論値を正しく接続する。

## 9. 残り12台

S079〜S090は、該当実機DBレコードの設定別機械割を順次接続する。

DBで値が未確認の台はカテゴリ平均で埋めず、`payoutSourceStatus = UNRESOLVED` として残す。

```text
payoutSourceStatus:
- REAL_DB
- PARTIAL
- UNRESOLVED
```

これにより仮値と実機根拠値をゲーム実装時に混同しない。

## 10. Day 2戦略比較への修正

前段のDay 2 A/B比較で使った「A+RT区分実績出玉率」の一括仮定は、最終方式では廃止する。

新方式:

```text
S059 gross
+ S060 gross
+ ...
+ S090 gross
= A+RT total gross
```

同様にOUT・SAFE・売上も32台の積み上げで求める。

これにより「A+RTに設定を使う」というプレイヤー判断を、実際には

- どの機種へ
- 何台
- 設定いくつを
- どの客期待がある日に

投入したかまで評価できる。
