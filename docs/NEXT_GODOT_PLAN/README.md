# 次期 Godot 構想メモ

更新日: 2026-09-21

> このフォルダは、現在の Godot 実装とは分離した「次に作り直す構想」の保管場所。
> 現行の `godot/`・`slot-pachiro-godot/`・DB・既存資料は変更しない。
> 宮古で開発再開時に、現行 Godot 部分を確認・退避したうえで新構成へ移行する。

## 1. ゲーム全体

ゲームは大きく2モードに分ける。

### 経営者モード
ホール全体を経営するモード。
店内を3D/2Dキャラクターで歩かせる方式ではなく、管理画面・台データを中心に表現する。
店舗レイアウト編集は現時点では採用しない。

### プレイヤーモード
1台のパチスロを実際に打つモード。
こちらは実機プレイの品質に力を入れる。
ゼルヴォルトを中心に、リール、停止制御、抽選、ボーナス/AT/CZ、液晶演出、ランプ、音、操作感などを作り込む。

## 2. 経営者モードの基本サイクル

```
【開店前】
   ↓
設定変更・据え置き
   ↓
新台導入 / 撤去
   ↓
営業開始
   ↓
【営業中】
客が来店
   ↓
各台が稼働
   ↓
売上・差枚・稼働が動く
   ↓
時間経過
   ↓
【閉店】
最終データ確定
   ↓
売上 / 粗利 / 稼働 / 客数を確認
   ↓
翌日の営業判断
   ↓
【翌日】
```

考え方:
- 開店前 = 判断
- 営業中 = 観察
- 閉店後 = 分析
- 表面の操作は軽くする
- 内部シミュレーションは現実的にする

## 3. 営業中のメイン表現

ホール内を描画するのではなく、実際のホールのデータ表示を見る感覚を狙う。

台ごとにデータカウンターを並べる。
主な表示候補:
- 台番号
- 総回転数
- BB / RB / AT等
- 現在ゲーム数
- 差枚
- スランプグラフ

時間経過に伴い各台の数値とスランプグラフが更新される。
客キャラクターを画面に出さなくても、稼働状況・出玉状況・島の強弱が分かるUIを目指す。

## 4. 経営者モードの機種表示

機種は重い実機シーンではなく、軽量な「機種カード」として扱う。

例:
- ゼルヴォルト
- 正面画像
- Aタイプ
- 爆裂型

表示用情報は簡潔にし、裏側では設定別スペック、出玉特性、人気、客層との相性などのシミュレーション用データを持たせる。

## 5. Chappy5 DB の活用

既存DBを経営者モードの機種マスタ/シミュレーション基盤として活用する方向。

想定:
```
Chappy5 DB
  ↓
機種基本情報 / スペック / タイプ / 特徴
  ↓
経営者モード用データ
  ↓
客の機種選択
設定別シミュレーション
稼働
当たり
差枚
スランプグラフ
売上・粗利
```

全機種を実機化する必要はない。
DBに十分な情報がある機種は経営者モードへ投入可能にし、その中の一部をプレイヤーモード用のフル実機として制作する構想。

## 10. 新機種アイデア: パチスロ版 Lucky Trigger

パチンコそのものを直ちに実装する代わりに、パチンコ的なゲーム性をパチスロへ取り込む案。

### PUSHボタンを Lucky Trigger にする
- パチスロ筐体のPUSHボタンをLT発動の象徴として使う。
- 特定条件成立時にPUSHボタンが「LUCKY TRIGGER」状態へ変化・発光する演出を想定。
- 押下を契機に、通常ATより上位の特別状態・超上位状態などへ移行するゲーム性を検討する。
- 単なる上位AT追加ではなく、パチンコ的な「突入率 × 継続率 × 振り分け」の考え方をパチスロへ取り込む方向。
- 将来的に遊創舎機の特徴的な共通ギミックとして展開する案も候補。

現時点ではアイデア保存のみ。数値・突入条件・性能・名称・ゼルヴォルトへの採用有無は未決定。


## 11. 経営者モード確定仕様（2026-09-21）

### 11.1 1日の基本フロー

```
【開店前】
設定変更 / 据え置き
入替予定があれば実施
↓
【営業開始】
↓
【営業中】
客の来店・台選択・遊技を内部シミュレーション
台データをリアルタイム更新
↓
【閉店】
台別・機種別の最終データ確定
↓
【営業結果 / ホルコン】
売上 / 粗利 / 稼働 / 客数 / 台別・機種別成績を確認
↓
翌日の営業判断
```

営業中の主表示はデータカウンターとスランプグラフ。ホール内の客や筐体を常時描画する方式にはしない。

### 11.2 台データカウンター

基本表示項目:
- 台番号 / 機種名
- BB
- RB
- 総スタート
- 現在スタート
- 差枚数
- スランプグラフ

機種固有の挙動・設定差・AT/CZ等はChappy5実機DBの機種データを基礎にシミュレーションする。

### 11.3 新台購入・入替

新台:
1. 購入する機種と台数を決定
2. 購入時に入替予定台を指定
3. 機械代は購入時に全額前払い
4. 導入待ち期間は5日
5. 5日後に指定台を撤去して新台を設置
6. 撤去台は売却せず倉庫へ移動
7. 新台の設定配分は導入当日の開店前に決定

倉庫台の再設置:
1. 倉庫から再設置する台を選択
2. 入替予定台を指定して申請
3. 機械購入費は発生しない
4. 申請期間は3日
5. 3日後に入替
6. 撤去された台は倉庫へ移動
7. 設定配分は導入当日の開店前に決定

### 11.4 客AI

固定された多数の客タイプではなく、少数の内部パラメータから個体差を生成する。

基本パラメータ:
- ガチ度 0〜100: 設定・データ・期待値を重視する度合い
- 好み 0〜100: 好きな機種・タイプを優先する度合い
- 投資力 0〜100: 使用可能金額・粘りやすさ
- ハイエナフラグ ON/OFF: 天井・ゾーン・スルー回数等の狙い目を探索する特殊行動

台選択・継続・ヤメ・移動・退店の具体的な判定値は、Godot上でシミュレーションを動かしながら調整する。

### 11.5 店舗の内部評価と集客

プレイヤーには直接数値を表示しない内部評価を持つ。

- 一般人気: エンジョイ層を中心とした通常集客に影響
- 期待度: ガチ層が店の営業内容を評価する指標

設定状況や実際の営業結果が翌日以降の客層・集客へ影響する。エンジョイ層だけ、またはガチ層だけに偏った営業が恒常的な最適解にならないよう調整する。

### 11.6 広告・来店イベント

広告系:
- 低〜中コスト
- 一般客を中心に集客
- 新台告知、通常広告等を想定

来店イベント系:
- 広告より高コスト
- 集客力が高い
- ガチ層や店の期待度にも影響
- ゲーム内オリジナル演者を使用可能
- 演者ごとに知名度、費用、得意客層、得意機種ジャンル等を持たせる方向

イベント当日の営業内容も内部評価へ反映し、「イベントを開催するだけ」が最適解にならない設計とする。

### 11.7 経費・収支

初期店舗は自社所有とし、家賃は0円。

経費は以下の6系統に整理する:
1. 人件費
2. 光熱費（電気代を中心に水道等を含む）
3. 遊技機費
4. 販促費（広告・来店イベント）
5. 設備・維持費
6. その他経費（通信、システム、保険等）

細かい経費は内部で自動計算し、プレイヤーが毎日操作するのは新台・人員・広告・イベント等の経営判断に関わる項目を中心とする。

基本収支:
```
遊技粗利
- 人件費
- 光熱費
- 遊技機費
- 販促費
- 設備・維持費
- その他経費
= 最終利益
```

### 11.8 店舗規模・多店舗展開

ゲーム開始時:
- 自社所有の小型1号店
- 48台スタート
- 家賃なし

1号店を無理に巨大化させることを前提にしない。資金・経営力が成長した段階で2号店、3号店と店舗展開できる構造を目標とする。

新店舗候補が持つ主な属性:
- 初期設置可能台数
- 土地の余白（小 / 中 / 大等）
- 将来の増築上限
- 立地による集客特性
- 土地・建物の取得価格

土地に余白がある店舗は将来的な増築が可能。余白が少ない店舗は小型店として維持する、移転する、別店舗を出す等の経営判断につなげる。

初期48台店は将来的に創業店として残すことも可能な設計とする。

## 13. 創業店の人員・経費・初期資金（確定）

### 13.1 48台創業店の従業員

初期店舗はプレイヤーが店長を兼任する。

- プレイヤー: 店長兼任
- ホールスタッフ: 4名
- 清掃: 1名
- 従業員合計: 5名
- 同時勤務: 内部シフト処理で2〜3名程度
- プレイヤーが毎日の詳細シフトを組む操作は採用しない

48台店では現時点で5名を初期基準とする。人員の適正値は営業シミュレーション時に再調整する。
減員すると人件費は下がるが、接客・清掃・トラブル対応等が悪化する。
増員すると営業は安定するが、人件費が増える。

多店舗化後は各店舗に店長を配置する方向とし、店舗数の増加に伴って人材管理の重要度を上げる。
個人単位の細かな育成・複雑なシフト管理は現段階では採用しない。

### 13.2 税金・公的負担

税務処理そのものをゲーム操作にはしない。
以下の3系統に簡略化して自動計算する。

1. 人件費関連負担
2. 固定系税金（土地・建物等）
3. 年度利益に対する税金（法人税等を簡略化）

消費税等の細かな申告操作は行わせず、必要に応じて内部計算または税・公課へまとめる。

### 13.3 48台店の月間基礎経費

初期基準:

| 項目 | 月額基準 |
| --- | ---: |
| 給与 | 120万円 |
| 人件費関連負担 | 18万円 |
| 電気・水道 | 26万円 |
| 通信・システム | 5万円 |
| 清掃・消耗品 | 5万円 |
| 設備維持・修繕 | 10万円 |
| 保険・その他 | 5万円 |
| **月間基礎経費** | **189万円** |

年間基礎経費の基準は約2,268万円。
固定系税金や利益課税は別途発生する。

### 13.4 光熱費

48台店の電気代は月24万円前後を中心値として扱い、水道等を加えて月26万円を基礎経費上の基準値とする。

電気代には季節変動を持たせる方向:
- 春・秋: 18〜21万円程度
- 夏: 28〜34万円程度
- 冬: 23〜28万円程度

最終的な変動幅はGodot上で年間シミュレーションを行い調整する。

### 13.5 遊技機購入価格

新台価格はゲーム内の基本基準を **1台約50万円** とする。

ただし全機種を固定50万円にはせず、機種・時期・市場条件による価格差を持たせられる構造にする。
中古台については新品とは別に市場価格が変動する仕組みを将来検討する。

### 13.6 初期資金

48台創業店の開始時運転資金は **3,500万円** で確定。

考え方:
- 自社所有店舗のため家賃0円
- 48台店の年間基礎経費は約2,268万円
- 残りを新台購入、販促、イベント、予備資金等に使う
- 十分な余裕資金を与えすぎず、投資判断を経営ゲームとして成立させる

新台を大量購入したり広告・イベントを過剰に実施すれば資金繰りが悪化する。
黒字営業によって投資余力を増やし、厳しい場合は入替延期・中古台活用・人員調整等で立て直す設計を目標とする。
