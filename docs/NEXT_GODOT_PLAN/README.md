# 次期 Godot 構想メモ

更新日: 2026-09-20

> このフォルダは、現在の Godot 実装とは分離した「次に作り直す構想」の保管場所。
> 現行の `godot/`・`slot-pachiro-godot/`・DB・既存資料は変更しない。
> 宮古で開発再開時に、現行 Godot 部分を確認・退避したうえで新構成へ移行する。

## 1. ゲーム全体

ゲームは大きく2モードに分ける。

### 経営者モード
ホール全体を経営するモード。
店内を3D/2Dキャラクターで歩かせる方式ではなく、管理画面・台データを中心に表現する。
店舗レイアウト編集は現時点では採用しない。

### プレイヤーモード
1台のパチスロを実際に打つモード。
こちらは実機プレイの品質に力を入れる。
ゼルヴォルトを中心に、リール、停止制御、抽選、ボーナス/AT/CZ、液晶演出、ランプ、音、操作感などを作り込む。

## 2. 経営者モードの基本サイクル

```
【開店前】
   ↓
設定変更・据え置き
   ↓
新台導入 / 撤去
   ↓
営業開始
   ↓
【営業中】
客が来店
   ↓
各台が稼働
   ↓
売上・差枚・稼働が動く
   ↓
時間経過
   ↓
【閉店】
最終データ確定
   ↓
売上 / 粗利 / 稼働 / 客数を確認
   ↓
翌日の営業判断
   ↓
【翌日】
```

考え方:
- 開店前 = 判断
- 営業中 = 観察
- 閉店後 = 分析
- 表面の操作は軽くする
- 内部シミュレーションは現実的にする

## 3. 営業中のメイン表現

ホール内を描画するのではなく、実際のホールのデータ表示を見る感覚を狙う。

台ごとにデータカウンターを並べる。
主な表示候補:
- 台番号
- 総回転数
- BB / RB / AT等
- 現在ゲーム数
- 差枚
- スランプグラフ

時間経過に伴い各台の数値とスランプグラフが更新される。
客キャラクターを画面に出さなくても、稼働状況・出玉状況・島の強弱が分かるUIを目指す。

## 4. 経営者モードの機種表示

機種は重い実機シーンではなく、軽量な「機種カード」として扱う。

例:
- ゼルヴォルト
- 正面画像
- Aタイプ
- 爆裂型

表示用情報は簡潔にし、裏側では設定別スペック、出玉特性、人気、客層との相性などのシミュレーション用データを持たせる。

## 5. Chappy5 DB の活用

既存DBを経営者モードの機種マスタ/シミュレーション基盤として活用する方向。

想定:
```
Chappy5 DB
  ↓
機種基本情報 / スペック / タイプ / 特徴
  ↓
経営者モード用データ
  ↓
客の機種選択
設定別シミュレーション
稼働
当たり
差枚
スランプグラフ
売上・粗利
```

全機種を実機化する必要はない。
DBに十分な情報がある機種は経営者モードへ投入可能にし、その中の一部をプレイヤーモード用のフル実機として制作する構想。

## 6. 共通機種構造の考え方

```
Machine
├─ identity
│  ├─ id
│  ├─ name
│  └─ front_image
├─ manager_metadata
│  ├─ type
│  └─ characteristic
├─ simulation_data
│  ├─ setting_specs
│  ├─ payout_characteristics
│  ├─ popularity
│  └─ customer_affinity
└─ player_machine
   └─ 完成している機種のみ実機Godotシーンを接続
```

経営者モードとプレイヤーモードで機種IDを共有できる形を目標とする。

## 7. Godot再構築方針（未実施）

現行Godot部分は今すぐ削除しない。

宮古で再開したら:
1. `godot/` と `slot-pachiro-godot/` の現状確認
2. 必要なゼルヴォルト関連資産・コードを特定
3. 退避すべきものを分離
4. 不要な旧3Dホール前提部分を整理
5. 次期構成を新規に作る
6. DBとの接続方法を決める

新しい大枠候補:
```
Game
├─ ManagerMode
│  ├─ PreOpen
│  ├─ MachineManagement
│  ├─ Business
│  └─ ClosingResults
├─ PlayerMode
│  └─ Machines
│      └─ Zelvolt
└─ Shared
   ├─ MachineData
   └─ Simulation
```

## 8. 現時点で固定しないもの

以下はまだアイデア段階。実装開始前に再検討する。
- 具体的な画面数
- UIレイアウト
- データカウンターの表示項目
- 時間進行速度
- 客シミュレーションの詳細
- 設定変更UI
- 新台導入/撤去のルール
- DBの最終スキーマ
- プレイヤーモードと経営者モードの行き来の仕様

## 9. 再開地点

次回は「コードを書く」より先に、
**経営者モードの開店前 → 営業中 → 閉店の各UIを決める**
ところから再開する。

その後、現行Godotを安全に整理して新構成へ移行する。
