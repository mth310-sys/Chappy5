# A+RT32台 OUT・遊技時間 現実値校正 v0.1

更新日: 2026-09-01

目的: 客AI駆動A+RT32台プロトタイプのOUTが現実のパチスロ稼働尺度から逸脱していないか検証し、ゲーム内部の遊技速度・占有時間・OUTの関係を定義する。

## 1. 現実側の基準

DK-SIS白書2024では、2023年のパチスロについて以下が示されている。

- 1時間当たり実稼動: **2,288枚**
- 2023年平均OUT: **8,091枚/台日**
- 2023年平均遊技時間: **3時間32分**
- 売上: 19,254円/台日
- 粗利: 2,652円/台日

また2025年上期のDK-SIS資料では20円パチスロの月別OUTは概ね8,660〜9,150枚、遊技時間は概ね3時間44分〜3時間57分で推移している。

これらは現代の市場値であり、2007年前後の5号機初期ホールを直接表すものではない。したがってゲーム開始店の目標値としてコピーせず、**OUTと遊技時間の物理的な換算・シミュレーション健全性確認**に使う。

## 2. 現プロトタイプの問題

`art32-day2-prototype.js` の客タイプ別 `hourlyOut` は390〜480枚/時。

これは「着席している1時間」の投入枚数として解釈すると、DK-SISの実遊技1時間2,288枚に対して約17〜21%しかなく、低すぎる。

一方でプロトタイプは1時間tickで、休憩・離席・着席タイミングを粗くまとめているため、`hourlyOut` が実遊技速度と占有率を二重に圧縮している。

したがって、現在の11〜12万OUT/32台という結果だけを見て「客が少ない」と判断してはいけない。まず時間モデルを直す必要がある。

## 3. 正しい分離

今後は以下を分ける。

```text
occupiedMinutes
activePlayRatio
outPerActiveHour
```

台iの1tick OUT:

```text
activeMinutes = occupiedMinutes × activePlayRatio
hourOut = outPerActiveHour × activeMinutes / 60
```

初期の物理基準:

```text
outPerActiveHour = 2,288枚/時
```

これは2023 DK-SIS基準。5号機時代差が確認できれば世代別に差し替える。

`activePlayRatio` で、着席中の休憩・データ確認・飲食・トイレ・ボーナス後の停止等を吸収する。

## 4. 現代平均との整合確認

8,091 OUT ÷ 2,288枚/時 = 約3.54時間。

これは2023年公表の遊技時間3時間32分（約3.53時間）とほぼ一致する。

よって、ゲーム内部でも

```text
OUT / outPerActiveHour ≒ activePlayHours
```

をQA指標にできる。

## 5. 開始ホールへどう使うか

開始ホールは弱い店なので、全国平均8,000〜9,000 OUTを目標にはしない。

既存の開始店A+RT目標レンジ4,000〜5,000 OUT/台日を仮に使う場合、2,288枚/時換算では実遊技時間は:

- 4,000 OUT → 約1.75時間/台日
- 4,700 OUT → 約2.05時間/台日
- 5,000 OUT → 約2.19時間/台日

13時間営業に対する実遊技時間率では約13.5〜16.8%。

弱った地方店の開始状態としては、現代全国平均よりかなり低稼働という設定と整合する方向。

ただし2007年前後の実ホール稼働データが取れれば再校正する。

## 6. 32台A+RTのレンジ

平均4,700 OUTなら:

```text
32 × 4,700 = 150,400 OUT/日
```

必要な総実遊技時間:

```text
150,400 ÷ 2,288 ≒ 65.73時間
```

32台×13時間 = 416台時間に対して、active play比率は約15.8%。

したがって以前の150,400 OUTというカテゴリ基準は、物理的に不可能な数字ではない。

一方、客AIプロトタイプの約114,000〜116,000 OUTなら:

```text
114,000 ÷ 32 = 3,563 OUT/台
3,563 ÷ 2,288 ≒ 1.56実遊技時間/台
```

これも弱い店として成立し得る。

結論: **11〜12万か15万かは、OUTそのものではなく来店客数・実遊技時間を決めてから判定する。**

## 7. コード修正方針

現行:

```text
hourlyOut = 390〜480
```

を廃止する。

客タイプには:

```text
activePlayRatio
sessionPersistence
breakTendency
```

を持たせる。

機械側/世代側に:

```text
outPerActiveHour
```

を持たせる。

初期値は2,288枚/時を校正基準とし、ゲーム内ではtick内のoccupiedMinutesを生成してOUTへ変換する。

## 8. QA基準

各営業日で自動検査:

```text
activePlayHours = totalOut / outPerActiveHour
```

とシミュレーション上の実遊技時間合計を比較する。

許容誤差を超えた場合はFAIL。

さらに:
- activePlayRatio > 1.0 を禁止
- occupiedMinutes > 780分/台を禁止
- 閉店後OUT増加を禁止
- 空席中OUT増加を禁止
- 同一客の同時複数台着席を禁止

## 9. 現時点の判断

- 以前の15万OUTを正解として客AIを合わせ込まない。
- 現プロトタイプの11〜12万OUTも正解と決めない。
- まず `hourlyOut` の二重圧縮を解消する。
- 来店数→着席時間→実遊技時間→OUTの順に計算する。
- 現代DK-SISは物理換算/QAの基準として使用し、5号機開始時代の営業値とは分離する。
