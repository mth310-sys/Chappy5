# Chappy5 Reality & Presentation Quality Standard

> Status: `ACTIVE_QUALITY_STANDARD_V1`
>
> Chappy5ではゲーム性と同格で、**実機感・実在感・演出品質**を追求する。
> 「ブラウザだから簡略化する」を品質上の理由として認めない。

## 1. 最上位品質目標

目標は「パチスロ風のWebゲーム」ではない。

**iPhoneの画面を見た瞬間に、そこに一台のパチスロ機が存在し、内部で機械・リール・液晶・LED・役物・音響が連動して動いていると感じられること。**

Visualが綺麗なだけではPASSしない。演出が派手なだけでもPASSしない。実在感、重量感、同期、操作への反応、遊技上の意味が成立して初めて完成候補とする。

## 2. REALITY / PRESENCE を独立評価軸とする

全主要制作工程・試作機・試打で `REALITY_PRESENCE` を独立評価する。

評価対象：

- 筐体の立体感、奥行き、素材感
- 金属、樹脂、ガラス、透明部品等の質感差
- リール窓の深さとリールの物理的存在感
- 光源としてのLEDと周囲への照り返し
- 液晶と筐体の輝度・奥行きの違い
- ボタンの押下、点灯、反応の手応え
- リール始動、加速、回転、減速、停止の慣性・重量感
- 役物の質量を感じる移動、加減速、停止、復帰
- 液晶、リール、LED、役物、Audioの同期
- 演出が遊技状態・抽選・停止操作と因果的につながっていること
- iPhone上での視認性と「一台の機械」としてのまとまり

## 3. Visual & Mechanism品質基準

Visual & Mechanism Directorは単なる画面装飾ではなく、機械としての存在感を担当する。

- 平面的な矩形の積み重ねだけで筐体完成としない。
- フレーム、リール窓、液晶、操作卓、役物に前後関係を持たせる。
- 発光部は単なる色変更ではなく、可能な範囲で周囲への光の影響を表現する。
- 素材ごとの反射・陰影・エッジ・透明感を区別する。
- リール停止は座標が止まるだけではなく、停止感を設計する。
- 可動役物は一定速度の単純移動を標準とせず、重量・目的に応じたモーションを設計する。
- 遊創舎の既存機構は、回転・反転・軸変更・合成等によってより実機らしい新機構へ発展させてよい。

## 4. 演出品質基準

演出は「派手なアニメーション」ではなく、時間軸を持った遊技体験として設計する。

例：

`LEVER ON → リール始動 → 液晶変化 → LED走行 → STOP1 → STOP2 → 間 → STOP3 → 役物 → Flash → 告知音 → BONUS表示 → BGM突入`

各演出では必要に応じて以下を仕様化する。

- 発火条件
- 開始タイミング
- 尺
- 停止操作との同期点
- Visual変化
- LED変化
- Mechanism動作
- Audio Event
- 数百ms単位を含む「間」
- 結果表示
- 次ゲームへの復帰

強い演出ほど長くすればよいとはしない。期待、緊張、停止、解放のリズムを優先する。

## 5. 同一Event駆動原則

実在感を守るため、液晶・LED・役物・Audioが互いに無関係なタイマーで勝手に動く構造を避ける。

可能な限り、ゲーム内部の同一Event／状態変化を起点として、

**Game Event → Reel / Visual / LED / Mechanism / Audio**

を同期させる。

これにより「たまたま同時にアニメーションしている」のではなく、「内部で起きた一つの出来事に機械全体が反応した」状態を作る。

## 6. 開発機での確認

統合開発機では機能確認だけでなく、REALITY / PRESENCEを確認する。

最低確認項目：

- BET時の視覚・押下・音の同期
- STARTからリール定速回転までの自然さ
- STOP1/2/3それぞれの停止感
- 出目確定と液晶／LED／Audioの因果
- 前兆・チャンスアップの期待度表現
- 当選時の停止→告知→役物→BGM遷移
- BONUS/AT中と通常時の空気の違い
- 終了・通常復帰時の自然さ

実画像未確認は `VISUAL_UNVERIFIED`。重要Audio未確認は `AUDIO_UNVERIFIED`。実ブラウザ操作未確認は `PLAYTEST_UNVERIFIED`。実在感を十分確認できていない場合は `REALITY_UNVERIFIED` とする。

## 7. Team TrialでのREALITY評価

試打では以下を独立して問う。

1. 一台の機械として存在して見えるか。
2. リールが「画像」ではなく回転体として感じられるか。
3. ボタンを押した結果を機械全体から感じられるか。
4. LEDが装飾ではなく光源として機能しているか。
5. 役物に重量感・機械感があるか。
6. 液晶・リール・役物・音が同じ出来事へ反応しているか。
7. 当たりの瞬間に視覚・操作・音響が一体となった解放感があるか。
8. 派手でも玩具的・安っぽく見える箇所がないか。
9. 実機らしさを優先した結果、iPhoneで操作・視認しづらくなっていないか。
10. 「もう一度レバーを叩きたい」と感じるか。

## 8. PASSルール

以下ではREALITY PASSを出さない。

- スクリーンショットだけ綺麗
- CSSエフェクトだけ派手
- LEDが単純点滅するだけ
- 役物が一定速度で座標移動するだけ
- リール停止が瞬間的で重量感がない
- 音が鳴るがVisual／操作と同期していない
- 各要素が別々のタイマーで動き、因果が感じられない
- 実ブラウザで確認していない

完成候補では、ゲーム性・数理・品質に加えて `REALITY_PRESENCE_VERIFIED` を要求する。

最終的な「本当に実機らしく感じるか」「演出が気持ちいいか」はHuman Gateを最優先する。
