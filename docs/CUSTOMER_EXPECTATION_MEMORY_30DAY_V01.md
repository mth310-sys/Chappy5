# 客AI 多層期待記憶 + 30日営業モデル v0.1

更新日: 2026-08-31

目的: 7日連続営業モデルで単一値だった `storeExpectation` を分解し、客が「店全体」「機種分類」「島」「曜日」の営業傾向を別々に学習できる30日モデルを定義する。

注意: 本文の係数・閾値・記憶速度はすべて検証用暫定値。正式採用値ではない。

## 1. なぜ単一の店舗期待では足りないか

客は店を一つの評価だけで覚えるとは限らない。

例:
- この店は全体的には弱い
- でもノーマルは扱いが良い
- N-01島は土曜に強い
- 強い日の翌日は回収されやすい

これらを一つの `storeExpectation` に潰すと、営業方針の個性が消える。

## 2. 期待記憶の4層

### StoreExpectation
店全体への基礎信頼。

### CategoryExpectation
機種分類ごとの期待。
例:
- NORMAL
- AT
- OKISLOT_30

現段階のN-01検証では NORMAL のみ使用する。

### IslandExpectation
特定島への期待。
同じNORMALでも島ごとに営業差を作れる。

### WeekdayExpectation
曜日ごとの営業傾向。
月〜日を別々に保持する。

## 3. 客が実際に使う期待

来店・着席時には4層を重み付けする。

暫定例:
`effectiveExpectation = store*0.30 + category*0.25 + island*0.30 + weekday*0.15`

重みは客タイプによって変えてよい。

常連・設定狙い客:
- island / weekday を重視

ライト客:
- store を重視
- 詳細な曜日癖をあまり学習しない

v0.1ではまず設定意識型常連だけで検証する。

## 4. 記憶更新

営業終了時に、客が観測可能だった公開結果から各期待を更新する。

基本候補:
`next = old*(1-alpha) + observed*alpha`

暫定学習率:
- Store: alpha 0.12
- Category: alpha 0.16
- Island: alpha 0.22
- Weekday: alpha 0.18

島は比較的早く学習し、店全体の評判はゆっくり変わる。

## 5. 記憶の不確実性

期待値だけでなく confidence を持たせる。

初来店客:
- confidence低

常連:
- 過去観測日数に応じてconfidence高

新台/新島:
- island confidenceを低く初期化

これにより1日だけ強い営業をしても、長年の弱い評判が完全反転しない。

## 6. 曜日学習

曜日期待は「土曜日に強い」を学習可能にする。

例:
月〜金: 低設定中心
土: メリハリ
日: メリハリ

数週間続けば:
- 土日のWeekdayExpectation上昇
- 平日のWeekdayExpectation低下

結果として、週末は開店時点から客数が増え得る。

これは単日の公開データによる午後稼働上昇とは別の因果。

`過去営業の記憶 → 朝の来店人数`

を作る。

## 7. 営業パターンを読まれる

同じパターンを反復すると客AIが学習する。

例:
日曜全台系 → 月曜回収

これを何週も繰り返すと:
- 日曜期待上昇
- 月曜期待低下

したがって店長が毎週同じ営業を続ければ、その癖自体が客行動へ反映される。

ただし客AIに未来の設定を直接教えない。あくまで過去統計から予想する。

## 8. 30日検証シナリオ

### P1 常時回収
30日すべてA低設定中心。

確認:
- 短期粗利
- 期待低下
- 月後半の来店母数低下
- 最終的に低設定でもアウト不足で利益が伸びなくなるか

### P2 週末還元
月〜金A、土日Cメリハリを4週間反復。

確認:
- 土日の朝稼働上昇
- 平日の回収力
- 月間黒字と信頼維持の両立

### P3 バランス営業
B中間中心を基本に、週1回C。

確認:
- 安定稼働
- 大幅赤字を避けながら期待維持できるか

### P4 強日→翌日回収固定
毎週特定曜日D全台系、その翌日A。

確認:
- 客が曜日パターンを学習するか
- 強日は朝から増え、翌日は避けられるか
- 単純なイベント回収ループが無限に通用しないか

### P5 不規則メリハリ
月内の複数日をCにするが曜日固定しない。

確認:
- 曜日期待は育ちにくい
- 店/カテゴリ/島期待だけが上昇するか
- 客に「いつ行ってもチャンスがある店」と見えるか

## 9. 30日で記録する指標

日次:
- 来店人数
- 島アウト
- 島売上
- 島粗利
- 朝10時着席数
- 19時着席数
- StoreExpectation
- CategoryExpectation
- IslandExpectation
- 当該WeekdayExpectation

月次:
- 総売上
- 総粗利
- 平均アウト
- 前半15日 vs 後半15日アウト
- 曜日別平均アウト
- 曜日別朝稼働
- 期待値の最終状態
- 常連再来店率（個体AI導入後）

## 10. 期待と来店母数の接続

重要: 期待値をアウトへ直接掛けない。

正しい因果:
`記憶 → 来店候補数/店選択 → 店内で台評価 → 着席 → 続行/移動 → games/out`

これにより「期待+0.5だからアウト+50%」のような機械的補正を避ける。

## 11. 新規客と常連

30日モデルでは来店母数を最低2系統へ分ける。

### 新規/偶発客
- 店の細かい営業癖を知らない
- 基礎流入がある
- 店舗評判の影響は受ける

### 常連候補
- 過去の自身の観測を保持
- category/island/weekdayを学習
- 良い経験で再来店確率上昇
- 弱い営業の反復で他店へ流出

これにより評判が下がっても来店客が完全ゼロになるのを防ぎつつ、常連基盤の形成/崩壊を表現する。

## 12. 競合店への拡張余地

将来、近所の大型競合を入れる際は同じ期待モデルを競合にも持たせる。

客は:
`自店effectiveExpectation` vs `競合effectiveExpectation` + 距離/好み/機種構成

で店選択する。

これによりゲーム冒頭の「近所に強い競合ができて客を奪われた」状態を、固定デバフではなく客AIの店選択として表現できる。

## 13. 現段階の設計判断

- 店舗信用を単一値だけで最終実装しない。
- 設定番号を客AIへ直接渡さない。
- 曜日営業を学習可能にする。
- 期待は直接アウト補正ではなく来店/着席判断を経由させる。
- 店全体の評判は島評価よりゆっくり変化させる。
- 30日試験値は正式バランスとして採用しない。

## 14. 次工程

このモデルを使ってP1〜P5を30日ずつ多数回試験し、以下を確認する。

1. 常時回収が月後半に稼働低下するか
2. 週末還元で曜日別朝稼働が形成されるか
3. 強日翌日回収が客に読まれるか
4. 不規則メリハリと曜日固定メリハリに異なる店の個性が生まれるか
5. 月間粗利と月末期待の間に単純な一択ではないトレードオフが生まれるか
