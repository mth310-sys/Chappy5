## Topic reason

Run 7 separated `RESPONSIBILITY RESOLVED` from `ATTENTION SET RELEASED`. Game/Reel, Visual/Mechanism and Sound then showed that closure can be carried by logical reel/state evidence and baseline restoration rather than an added ALL CLEAR cue. Playtest & QA Run 8 exposed the remaining machine-level ambiguity: quiet behavior after an event can mean genuine closure, disengagement, latent obsolete duty, or global over-closure.

The machine therefore needs a research model in which closure retires a specific responsibility binding without muting unrelated duties or weakening the authority of later legitimate deviations.

## Prior unknown

The previous Attention Contract was still too serial:

`... -> RESPONSIBILITY RESOLVED -> CLOSURE EVIDENCE -> ATTENTION SET RELEASE -> TRUST UPDATE -> LOW-MONITORING REST`

That wording can be misread as one global machine state moving from ALERT back to CALM. Real repeated play can contain overlapping obligations: a small-role aiming duty may close while a bonus-inference question remains open; a temporary RT procedure can end while normal reel-reading remains continuously valid; one auditory cue can expire while a later valid deviation must still be able to reopen attention.

## Investigation

This run integrated the latest specialist chain rather than reopening a completed Case Study:

- Game & Reel Run 7: closure is responsibility-specific; one duty closing can open another; routine re-chunking requires the next action law to be legible.
- Visual & Mechanism Run 7: closure evidence should persist through touch/occlusion and return ownership to the normal visual grammar rather than add an ALL CLEAR surface.
- Sound & Experience Run 7: auditory release should restore listening grammar without requiring a new release sound; audio must not close a question the reels keep open.

## New learning

### 1. Responsibility should be represented as bindings, not a global attention mode

Research abstraction:

`RESPONSIBILITY_BINDING = {QUESTION, EVIDENCE_SOURCE, ACTION_LAW, END_CONDITION, REOPEN_CONDITION}`

This is not an implementation schema. It is a way to prevent the Machine Director from treating all attention as one scalar alertness value.

A player may simultaneously have:
- one binding retired;
- another binding still active;
- baseline routine compressed;
- future legitimate deviations still authorized to open a new binding.

Therefore:

`CLOSURE = SELECTIVE RETIREMENT OF A BINDING, NOT GLOBAL CALM.`

### 2. Resolution and retirement are distinct

A question can be mechanically resolved before the player's obsolete action tendency is actually retired.

Machine-level sequence:

`BINDING OPEN -> EVIDENCE / ACTION -> LOGICAL RESOLUTION -> END CONDITION LEGIBLE -> OBSOLETE BINDING RETIRES -> BASELINE RE-CHUNKS`

Run 8 adds one more acceptance condition:

`FUTURE VALID REOPENING REMAINS POSSIBLE.`

Thus:

`HEALTHY CLOSURE = RETIRE THE OLD DUTY WITHOUT RETIRING THE CHANNEL.`

### 3. Closure authority is local

The surface that legitimately resolves a duty should normally have first claim on closing it. If reel evidence resolves a reel question, unrelated audio or display should not globally declare the machine safe-to-ignore. If a temporary audio instruction expires because its action law no longer applies, the audio channel can return to baseline without implying that all reel inference has ended.

`THE SOURCE THAT CLOSES A DUTY DOES NOT AUTOMATICALLY CLOSE OTHER DUTIES.`

### 4. Reopenability is part of closure quality

A system that achieves low monitoring by teaching the player to ignore a channel has not achieved trustworthy invisibility. The correct post-closure state is not deafness/blindness; it is selective low monitoring with preserved discrimination.

`TRUSTWORTHY INVISIBILITY = LOW BASELINE MONITORING + PRESERVED LEGITIMATE REOPENABILITY.`

This extends Machine Run 6.

### 5. Attention Contract should be a set of local lifecycles

Revised research-only contract:

`STABLE BASELINE / MONITORING COMPRESSION`

plus zero or more local lifecycles:

`LEGITIMATE DEVIATION -> BINDING OPEN -> SOURCE AUTHORITY -> ACTION / EVIDENCE -> LOGICAL RESOLUTION -> CLOSURE EVIDENCE -> BINDING RETIRED`

followed by:

`ROUTINE RE-CHUNKING + TRUST UPDATE`

while other bindings may remain open and later deviations may create new bindings.

This avoids a false global sequence in which the whole machine becomes CALM whenever one local question ends.

## Changed understanding

Before Run 8, closure could still be imagined as a final phase after an interruption. The stronger model is **selective responsibility topology**: repeated play consists of a stable compressible baseline plus temporary, source-bound obligations with independent lifetimes.

The machine should not maximize closure speed. It should maximize **correct retirement**: obsolete duties stop consuming attention, unresolved duties retain authority, and future valid cues remain detectable.

## Reusable principles

- `CLOSURE = SELECTIVE RETIREMENT OF A BINDING, NOT GLOBAL CALM.`
- `HEALTHY CLOSURE RETIRES THE OLD DUTY WITHOUT RETIRING THE CHANNEL.`
- `ONE DUTY MAY CLOSE WHILE ANOTHER REMAINS OPEN.`
- `THE SOURCE THAT CLOSES A DUTY DOES NOT AUTOMATICALLY CLOSE OTHER DUTIES.`
- `A CLOSED DUTY SHOULD STOP CLAIMING ATTENTION; A VALID FUTURE DEVIATION SHOULD STILL BE ABLE TO EARN IT.`
- `TRUSTWORTHY INVISIBILITY REQUIRES PRESERVED REOPENABILITY.`
- `LOW MONITORING WITHOUT PRESERVED DISCRIMINATION IS DISENGAGEMENT, NOT MASTERY.`
- `DO NOT USE AN ALL-CLEAR CUE TO COLLAPSE A MULTI-DUTY MACHINE INTO A FALSE GLOBAL CALM STATE.`
- `THE ATTENTION CONTRACT IS A SET OF LOCAL LIFECYCLES OVER A COMPRESSIBLE BASELINE.`
- `CORRECT RETIREMENT MATTERS MORE THAN FAST RETIREMENT.`

## Limits / misuse

- This is a research abstraction, not a runtime state machine or code architecture.
- It does not specify timing thresholds, cue probabilities, reel control, presentation intensity or original-machine rules.
- It must not be used to justify copying 新ハナビ or any third-party cue/action mapping.
- It does not authorize Human Trial, browser play, fault injection, implementation, prototype or asset work.
- `CLOSURE INTEGRITY` remains a future Human-QA claim; desk research cannot certify it.
