## 1. Topic reason

Playtest & QA Run 7 exposed a whole-machine gap: a temporary responsibility can be resolved mechanically while the Human remains vigilant for it. Existing Machine work already defined monitoring compression, trustworthy invisibility, responsibility reopening, source authority, causal trust and low-monitoring rest, but did not explicitly separate physical cue termination from closure of the player's active task-set.

## 2. Prior unknown

The unresolved question was: **what constitutes a legitimate whole-machine closure rule after a temporary responsibility event?**

A naive model was:

`cue ends -> responsibility ends -> REST`

This is insufficient because the Human can continue checking, waiting, listening or searching after the cue has physically disappeared.

## 3. Investigation

This run integrates the completed real-machine anchors and specialist findings already recorded on main without reopening closed Case Study work or refining an original concept.

Closed 新ハナビ evidence is used only as a structural anchor: stable lever/three-STOP hardware supports a low-duty ordinary loop, temporary role/RT/technical-intervention responsibilities can open, and ordinary reel-centered play resumes afterward. No protected sound, visual, stop-control table, melody, waveform or cabinet design is copied.

The integration also uses Playtest & QA Run 7's distinction between correct cue response and post-cue vigilance, Game & Reel's selective de-automation model, Visual & Mechanism's local responsibility reopening, and Sound & Experience's `OPEN -> HOLD -> RELEASE` model.

## 4. New learning

### 4.1 Closure is a state transition, not disappearance

`RESPONSIBILITY RESOLVED != ATTENTION SET RELEASED`

A whole-machine event is not cognitively closed merely because its lamp, sound, instruction or transient state ended.

A stronger sequence is:

`LOW-MONITORING REST -> LEGITIMATE DEVIATION -> RESPONSIBILITY OPEN -> RESPONSIBILITY ACTION -> EVIDENCE RESOLUTION -> CLOSURE EVIDENCE -> MONITORING RELEASE -> LOW-MONITORING REST`

### 4.2 Closure requires positive evidence of ordinary law returning

The machine should not require a second celebratory signal that says "stop paying attention." Instead, closure can be established when the temporary exception has a legible terminal condition and the familiar baseline law resumes predictably.

`CLOSURE AUTHORITY = LEGIBLE END CONDITION + TRUSTED BASELINE RETURN`

The end condition may be state completion, resolved reel evidence, completion of a temporary action duty, or another documented causal boundary. It must be attributable to the responsibility that opened, rather than merely coincident with an audiovisual tail ending.

### 4.3 Release is earned by restored predictability

`ATTENTION RELEASE SHOULD FOLLOW RESTORED PREDICTABILITY, NOT FORCED DISTRACTION.`

A machine should not need to pull attention elsewhere to make the player forget the previous task. The stronger outcome is that ordinary behavior becomes safe to compress again because the previous exception is demonstrably over.

### 4.4 Reopening and closure must be symmetric in responsibility, not intensity

If a cue opens a responsibility, the closing boundary should resolve that same responsibility. A large opening followed by an ambiguous ending creates monitoring debt; an oversized closing celebration can itself open a new attention claim.

`OPENING SAYS WHAT CHANGED; CLOSURE PROVES THAT CHANGE NO LONGER GOVERNS.`

### 4.5 Whole-machine attention contract

Research-only integration:

`STABLE BASELINE -> MONITORING COMPRESSION -> LEGITIMATE DEVIATION -> RESPONSIBILITY OPEN -> SOURCE AUTHORITY -> ACTION / EVIDENCE ACCUMULATION -> RESPONSIBILITY RESOLVED -> CLOSURE EVIDENCE -> ATTENTION SET RELEASE -> TRUST UPDATE -> LOW-MONITORING REST`

This is not an implementation specification. It is a falsifiable research model for later Human-authorized trials.

## 5. Changed understanding

Previous Machine work treated `resolution -> release` too compactly. Run 7 inserts two distinct boundaries:

1. `RESPONSIBILITY RESOLVED` — the temporary game/mechanical obligation is objectively finished.
2. `ATTENTION SET RELEASED` — the Human has actually returned toward baseline monitoring policy.

The machine can pass the first and fail the second.

Therefore:

`CORRECT MACHINE RESOLUTION + PERSISTENT HUMAN VIGILANCE = INCOMPLETE CLOSURE`

and:

`APPARENT CALM + LOST DEVIATION DISCRIMINATION = DESENSITIZATION, NOT RELEASE`

## 6. Reusable principles

- `RESPONSIBILITY RESOLVED != ATTENTION SET RELEASED.`
- `A TEMPORARY MACHINE STATE NEEDS A LEGIBLE COGNITIVE EXIT, NOT ONLY A TECHNICAL EXIT.`
- `CLOSURE AUTHORITY = LEGIBLE END CONDITION + TRUSTED BASELINE RETURN.`
- `OPENING SAYS WHAT CHANGED; CLOSURE PROVES THAT CHANGE NO LONGER GOVERNS.`
- `ATTENTION RELEASE SHOULD FOLLOW RESTORED PREDICTABILITY, NOT FORCED DISTRACTION.`
- `AN AMBIGUOUS END CONDITION CREATES MONITORING DEBT AFTER THE EVENT IS OVER.`
- `A CLOSURE CUE THAT DEMANDS NEW INTERPRETATION MAY OPEN ANOTHER TASK INSTEAD OF CLOSING THE OLD ONE.`
- `LOW-MONITORING REST IS RE-ENTERED WHEN ORDINARY LAW IS TRUSTWORTHY AGAIN, NOT WHEN PRESENTATION SIMPLY BECOMES QUIET.`
- `WHOLE-MACHINE CLOSURE MUST AGREE ACROSS GAME, REEL, VISUAL, MECHANISM AND AUDIO.`
- `RELEASE QUALITY IS TEMPORAL: IT INCLUDES WHAT THE PLAYER DOES IN THE ORDINARY GAMES AFTER RESOLUTION.`

## 7. Limits / misuse

Do not convert this research model into an original-machine cue table, timing table, UI, sound, lamp pattern or state design before Human Gate.

Do not infer that every responsibility needs an explicit audiovisual "all clear". That can create redundant signaling and a new monitoring burden.

Do not treat reduced checking alone as proof of release; preserved discrimination remains required.

Do not infer proprietary 新ハナビ stop control or protected presentation details.

## 8. Remaining unknowns

- How much ordinary baseline evidence is sufficient for a Human to infer closure without explicit confirmation?
- Which responsibility classes can close through reel/state evidence alone, and which require cross-channel confirmation?
- How do overlapping temporary responsibilities close without one channel falsely implying global REST?
- How does interruption/resume on iPhone affect closure memory and monitoring policy?
- How should later Human trials distinguish healthy rapid release from premature disengagement?
